# 1) ClusterIP

원문 : https://cafe.naver.com/kubeops/498 (1. ClusterIP)

클러스터 **내부에서만** 접근 가능한 기본 Service 타입.
Pod IP는 재생성할 때마다 바뀌지만 Service IP는 고정이라는 것을 확인하는 것이 목적이다.

## 실습 시작 전 정리

```bash
clear                       # 화면 정리 후 시작

# default 네임스페이스의 실습 리소스를 전부 삭제 (시스템 네임스페이스는 건드리지 않는다)
kubectl delete pod,deploy,rs,statefulset,daemonset,job,cronjob \
  --all -n default --grace-period=1 --ignore-not-found

# Service는 kubernetes(클러스터 기본 서비스)만 남기고 삭제
kubectl delete svc -n default \
  --field-selector 'metadata.name!=kubernetes' --ignore-not-found

kubectl get all -n default  # service/kubernetes 만 남으면 정상
```

> **`-n default`를 반드시 붙인다.** `-A`(전 네임스페이스)로 실행하면 `kube-system`,
> `calico-system` 등 클러스터 구동에 필요한 리소스까지 지워져 **클러스터가 망가진다.**

## YAML

```yaml
apiVersion: v1                                 # Pod은 core 그룹
kind: Pod
metadata:
  name: pod-1                                  # Pod 이름
  labels:
    app: pod                                   # Service가 이 라벨로 찾아온다
spec:
  nodeSelector:
    kubernetes.io/hostname: k8s-worker1        # worker1에 고정 (뒤 NodePort 실습에서 위치가 중요)
  containers:
  - name: container
    image: kubetm/app                          # /hostname 으로 자기 Pod 이름을 응답하는 이미지
    ports:
    - containerPort: 8080                      # 컨테이너가 실제로 bind 하는 포트
---
apiVersion: v1                                 # Service도 core 그룹
kind: Service
metadata:
  name: svc-1
spec:
  selector:
    app: pod                                   # app=pod 라벨을 가진 Pod 전부가 대상
  ports:
  - port: 9000                                 # Service가 받는 포트
    targetPort: 8080                           # Pod으로 전달할 포트 (containerPort와 일치)
                                               # type 생략 → 기본값 ClusterIP
```

## 실습 과정

### 1. 생성

```bash
clear                                                        # 화면 정리 후 시작
kubectl apply -f - <<'END'                                   # Pod과 Service를 한 번에 생성 (YAML은 위 절 참고)
# ... 위 YAML 전체 ...
END

kubectl wait --for=condition=Ready pod/pod-1 --timeout=120s  # Pod이 뜰 때까지 대기
kubectl get pod pod-1 -o wide                                # Pod IP와 노드 확인
kubectl get svc svc-1                                        # Service IP 확인
```

```
NAME    READY   STATUS    IP               NODE
pod-1   1/1     Running   20.100.194.124   k8s-worker1

NAME    TYPE        CLUSTER-IP      EXTERNAL-IP   PORT(S)    AGE
svc-1   ClusterIP   10.110.64.224   <none>        9000/TCP   0s
```

`EXTERNAL-IP`가 `<none>`이다. **클러스터 밖에서는 이 주소로 못 들어온다.**

Pod IP(`20.100.194.x`)와 Service IP(`10.110.64.x`)는 **대역이 다르다.**
Pod IP는 CNI(Calico)가 주고, Service IP는 `--service-cluster-ip-range`에서 나온다.

### 2. Service IP로 호출

```bash
clear                                                        # 화면 정리 후 시작
IP=$(kubectl get svc svc-1 -o jsonpath='{.spec.clusterIP}')  # Service IP를 변수에 담는다
curl $IP:9000/hostname                                       # Service의 9000 → Pod의 8080 으로 전달된다
```

```
Hostname : pod-1
```

Service의 `port`(9000)로 보냈는데 Pod의 `targetPort`(8080)로 도착했다.
**두 포트는 달라도 된다.** Service가 중간에서 바꿔준다.

### 검증: Pod IP는 휘발성, Service IP는 영구적

원문의 *"Pod의 IP는 휘발성이기 때문에, 영구적인 Service의 IP를 통해서 연결"* 을 확인한다.

Pod을 지웠다가 **같은 yaml로 다시 만든다.**

```bash
clear                                                        # 화면 정리 후 시작
kubectl get pod pod-1 -o jsonpath='{.status.podIP}'          # 삭제 전 Pod IP
kubectl delete pod pod-1 --grace-period=1                    # Pod만 삭제 (Service는 그대로)
kubectl apply -f - <<'END'                                   # 같은 정의로 재생성
# ... pod-1 YAML ...
END
kubectl wait --for=condition=Ready pod/pod-1 --timeout=120s  # 다시 뜰 때까지 대기
kubectl get pod pod-1 -o jsonpath='{.status.podIP}'          # 삭제 후 Pod IP
kubectl get svc svc-1 -o jsonpath='{.spec.clusterIP}'        # Service IP는 그대로인가
```

```
삭제 전  Pod IP: 20.100.194.124   /   Service IP: 10.110.64.224
삭제 후  Pod IP: 20.100.194.125   /   Service IP: 10.110.64.224
                          ↑ 바뀜                        ↑ 그대로
```

Pod IP는 바뀌었는데 Service IP는 그대로다. 그리고 **같은 Service IP로 호출이 여전히 된다.**

```bash
clear                             # 화면 정리 후 시작
curl 10.110.64.224:9000/hostname  # 재생성 후에도 같은 주소로 접근되는가
kubectl get endpoints svc-1       # Service가 새 Pod IP를 어떻게 알았나
```

```
Hostname : pod-1

NAME    ENDPOINTS             AGE
svc-1   20.100.194.125:8080   21s      ← 새 Pod IP로 자동 갱신
```

**Endpoints가 자동으로 갱신됐다.** Service는 Pod의 *이름*이나 *IP*를 기억하지 않는다.
`selector`에 맞는 Pod을 계속 찾아서 Endpoints를 다시 채운다.

이것이 "Pod IP를 직접 쓰지 말고 Service를 쓰라"는 말의 실체다.

## 배운 것

- ClusterIP는 **클러스터 내부 전용**이다. `EXTERNAL-IP`가 `<none>`이다.
- `port`(Service가 받는 포트)와 `targetPort`(Pod의 포트)는 달라도 된다.
- Pod IP는 재생성마다 바뀌지만 Service IP는 고정이다.
- Service는 Pod의 이름·IP가 아니라 **라벨**을 보고 Endpoints를 계속 갱신한다.
