# 2) HPA — CPU 사용률(Utilization)로 늘리기

원문 : https://cafe.naver.com/kubeops/530 (2-1, 2-2)

지금까지 `replicas` 는 사람이 정했다(`kubectl scale`).
HPA는 **부하를 보고 스스로 늘리고 줄인다.**

## 왜 필요한가

### 없으면 이렇게 된다

[1. Metrics Server](1.metrics-server.md)로 사용량은 볼 수 있게 됐다.
하지만 보는 것과 **대응하는 것**은 다르다. 여전히 사람이 `kubectl scale`을 쳐야 한다.

새벽 3시에 트래픽이 몰리면 그때 깨어 있는 사람이 있어야 하고,
몰린 뒤에 늘리면 **이미 사용자는 느린 화면을 봤다.**

### HPA가 자동화하는 것

HPA는 주기적으로 사용량을 확인해 **`replicas`를 스스로 조절한다.**

```
CPU 50% 목표  ──▶  지금 80%  ──▶  Pod 늘림
              ──▶  지금 20%  ──▶  Pod 줄임
```

여기서 반드시 알아야 할 전제가 하나 있다.
**HPA는 `resources.requests`를 기준으로 사용률을 계산한다.**

```
사용률 = 현재 사용량 / requests
```

그래서 **`requests`가 없으면 HPA는 동작하지 않는다.**
`<unknown>`만 뜨고 아무 일도 일어나지 않는다.
[497 3](../497.pod-container-label-nodeschedule/3.pod-nodeschedule.md)에서
"requests는 장부상의 예약"이라고 했는데, 그 장부가 여기서 **기준값**으로 쓰인다.

늘리고 줄이는 속도도 대칭이 아니다.
**늘릴 때는 빠르게, 줄일 때는 천천히** 움직인다.
성급히 줄였다가 다시 늘리는 요동(flapping)을 막기 위해서다.

### 이 문서에서 확인할 것

- `requests`가 없으면 정말 동작하지 않는가 (2절)
- 부하를 주면 몇 개까지 어떤 속도로 늘어나는가 (3절)
- 부하를 멈추면 **얼마 만에** 줄어드는가 (4절)
- HPA가 무엇을 근거로 판단했는지 볼 수 있는가 (4절)

## 실습 시작 전 정리

```bash
clear                       # 화면 정리 후 시작

# default 네임스페이스의 실습 리소스를 전부 삭제 (시스템 네임스페이스는 건드리지 않는다)
kubectl delete pod,deploy,rs,statefulset,daemonset,job,cronjob \
  --all -n default --grace-period=1 --ignore-not-found

# Service는 kubernetes(클러스터 기본 서비스)만 남기고 삭제
kubectl delete svc -n default \
  --field-selector 'metadata.name!=kubernetes' --ignore-not-found

# HPA도 비운다 (metrics-server는 kube-system이라 남는다)
kubectl delete hpa --all -n default --ignore-not-found

kubectl get all -n default  # service/kubernetes 만 남으면 정상
```

> **`-n default`를 반드시 붙인다.** `-A`(전 네임스페이스)로 실행하면 `kube-system`,
> `calico-system` 등 클러스터 구동에 필요한 리소스까지 지워져 **클러스터가 망가진다.**
>
> metrics-server는 `kube-system`이라 지워지지 않는다.

## YAML

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: stateless-cpu1
spec:
  selector:
    matchLabels:
      resource: cpu
  replicas: 2
  template:
    metadata:
      labels:
        resource: cpu
    spec:
      containers:
      - name: container
        image: kubetm/app:v1
        resources:
          requests:
            cpu: 10m                           # ★ HPA 는 이 값을 기준으로 % 를 계산한다
          limits:
            cpu: 20m
---
apiVersion: v1
kind: Service
metadata:
  name: stateless-svc1
spec:
  selector:
    resource: cpu
  ports:
  - port: 8080
    targetPort: 8080
    nodePort: 30001                            # 부하를 넣을 입구
  type: NodePort
```

> **`resources.requests` 가 반드시 있어야 한다.**
> `Utilization` 은 "requests 대비 몇 %" 이므로 기준값이 없으면 계산 자체가 안 된다.
> 이것이 HPA를 붙일 때 가장 흔한 실수다.

```yaml
apiVersion: autoscaling/v2                     # v1 이 아니라 v2 를 쓴다
kind: HorizontalPodAutoscaler
metadata:
  name: hpa-resource-cpu
spec:
  maxReplicas: 10                              # 이 이상 안 늘린다
  minReplicas: 2                               # 이 이하로 안 줄인다
  scaleTargetRef:                              # 무엇을 조절할지
    apiVersion: apps/v1
    kind: Deployment
    name: stateless-cpu1
  metrics:
  - type: Resource
    resource:
      name: cpu
      target:
        type: Utilization                      # requests 대비 비율로 판단
        averageUtilization: 50                 # 평균 50% 를 유지하도록
```

## 실습 과정

### 1. 생성과 초기 상태

```bash
clear                                                        # 화면 정리 후 시작
kubectl apply -f - <<'END'                                   # Deployment, Service, HPA 생성
# ... 위 YAML 전체 ...
END

kubectl rollout status deploy/stateless-cpu1 --timeout=240s  # Pod 이 뜰 때까지
kubectl get hpa                                              # HPA 상태 (수집까지 30초 정도 걸린다)
```

```
NAME               REFERENCE                   TARGETS   MINPODS   MAXPODS   REPLICAS
hpa-resource-cpu   Deployment/stateless-cpu1   0%/50%    2         10        2
```

`TARGETS` 의 `0%/50%` 는 **현재/목표**다. 부하가 없으니 0%다.

### 2. 부하를 넣고 지켜본다

```bash
clear  # 화면 정리 후 시작
# 백그라운드로 요청을 계속 보낸다 (두 줄기로)
( for i in $(seq 1 4000); do curl -s --max-time 2 192.168.56.30:30001/hostname >/dev/null; done ) &
( for i in $(seq 1 4000); do curl -s --max-time 2 192.168.56.30:30001/hostname >/dev/null; done ) &

# 15초 간격으로 HPA 를 본다
for i in $(seq 1 12); do
  printf "  [%3ds] %s\n" $((i*15)) "$(kubectl get hpa hpa-resource-cpu --no-headers | awk '{print "TARGETS="$3"  REPLICAS="$6}')"
  timeout 15 tail -f /dev/null
done
```

```
  [ 15s] TARGETS=0%/50%     REPLICAS=2
  [ 30s] TARGETS=10%/50%    REPLICAS=2
  [ 45s] TARGETS=35%/50%    REPLICAS=2
  [ 60s] TARGETS=155%/50%   REPLICAS=2      ← 목표를 크게 넘었다
  [ 75s] TARGETS=155%/50%   REPLICAS=4      ← 늘기 시작
  [ 90s] TARGETS=140%/50%   REPLICAS=7
  [120s] TARGETS=95%/50%    REPLICAS=10     ← maxReplicas 도달
  [135s] TARGETS=8%/50%     REPLICAS=10     ← 부하 끝, 사용률 급락
```

**2 → 4 → 7 → 10.** 한 번에 10으로 가지 않고 단계적으로 늘린다.
기본 정책이 "한 번에 최대 2배 또는 4개"라서다.

```bash
clear                                                       # 화면 정리 후 시작
kubectl describe hpa hpa-resource-cpu | grep -A6 '^Events'  # 판단 근거를 남긴 이벤트
```

```
Normal  SuccessfulRescale  New size: 4; reason: cpu resource utilization (percentage of request) above target
Normal  SuccessfulRescale  New size: 7; reason: cpu resource utilization (percentage of request) above target
```

**왜 늘렸는지가 기록된다.** HPA가 예상대로 안 움직이면 여기부터 본다.

### 3. 줄어드는 데는 시간이 걸린다

부하를 멈춘 뒤에도 한동안 10개를 유지한다.

```bash
clear  # 화면 정리 후 시작
for i in $(seq 1 22); do
  printf "  [%3ds] %s\n" $((i*15)) "$(kubectl get hpa hpa-resource-cpu --no-headers | awk '{print "TARGETS="$3"  REPLICAS="$6}')"
  timeout 15 tail -f /dev/null
done
```

```
  [ 15s] TARGETS=10%/50%  REPLICAS=10
  ...
  [225s] TARGETS=2%/50%   REPLICAS=10      ← 4분 가까이 그대로
  [240s] TARGETS=10%/50%  REPLICAS=2       ← 여기서 한 번에 줄었다
  [330s] TARGETS=10%/50%  REPLICAS=2
```

**약 4분 뒤에야 줄었고, 그것도 한 번에 2까지.**

늘릴 때와 줄일 때의 태도가 다르다.

| | 늘릴 때 | 줄일 때 |
|---|---|---|
| 반응 속도 | 빠름 (15초 주기로 즉시) | **느림 (기본 5분 안정화 창)** |
| 이유 | 늦으면 서비스가 죽는다 | 성급히 줄이면 다시 늘려야 한다 |

부하가 오르내릴 때 Pod이 요동치는 것(flapping)을 막기 위한 설계다.
조절하려면 `behavior.scaleDown.stabilizationWindowSeconds` 를 쓴다.

### 정리

```bash
clear                                                   # 화면 정리 후 시작
kubectl delete hpa hpa-resource-cpu --ignore-not-found  # 다음 실습을 위해 HPA 부터 지운다
```

## 배운 것

- HPA는 **`resources.requests` 를 기준으로** 사용률을 계산한다. requests가 없으면 동작하지 않는다.
- `autoscaling/v2` 를 쓴다. `metrics` 배열로 여러 지표를 함께 볼 수 있다.
- 늘릴 때는 **단계적으로** 올린다 (2 → 4 → 7 → 10).
- **줄일 때는 5분 정도 기다린다.** 요동을 막기 위한 안정화 창이다.
- `kubectl describe hpa` 의 Events에 **판단 근거**가 남는다.
