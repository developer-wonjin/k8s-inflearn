# 3) HPA — 메모리 절대값(AverageValue)으로 늘리기

원문 : https://cafe.naver.com/kubeops/530 (2-3, 2-4)

[2번](2.hpa-cpu.md)은 `Utilization`(requests 대비 %)이었다.
이번엔 `AverageValue` — **Pod당 평균 사용량의 절대값**을 목표로 삼는다.

| target type | 판단 기준 | 표시 |
|---|---|---|
| `Utilization` | requests 대비 **%** | `35%/50%` |
| `AverageValue` | Pod당 평균 **절대값** | `9582592/5Mi` |

## 실습 시작 전 정리

```bash
clear                       # 화면 정리 후 시작

# default 네임스페이스의 실습 리소스를 전부 삭제 (시스템 네임스페이스는 건드리지 않는다)
kubectl delete pod,deploy,rs,statefulset,daemonset,job,cronjob \
  --all -n default --grace-period=1 --ignore-not-found

# Service는 kubernetes(클러스터 기본 서비스)만 남기고 삭제
kubectl delete svc -n default \
  --field-selector 'metadata.name!=kubernetes' --ignore-not-found

# HPA도 비운다 (metrics-server는 kube-system이라 남는다)
kubectl delete hpa --all -n default --ignore-not-found

kubectl get all -n default  # service/kubernetes 만 남으면 정상
```

> **`-n default`를 반드시 붙인다.** `-A`(전 네임스페이스)로 실행하면 `kube-system`,
> `calico-system` 등 클러스터 구동에 필요한 리소스까지 지워져 **클러스터가 망가진다.**
>
> metrics-server는 `kube-system`이라 지워지지 않는다.

## YAML

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: stateless-memory1
spec:
  selector:
    matchLabels:
      resource: memory
  replicas: 2
  template:
    metadata:
      labels:
        resource: memory
    spec:
      containers:
      - name: container
        image: kubetm/app:v1
        resources:
          requests:
            memory: 5Mi
          limits:
            memory: 20Mi
---
apiVersion: autoscaling/v2
kind: HorizontalPodAutoscaler
metadata:
  name: hpa-resource-memory
spec:
  maxReplicas: 10
  minReplicas: 2
  scaleTargetRef:
    apiVersion: apps/v1
    kind: Deployment
    name: stateless-memory1
  metrics:
  - type: Resource
    resource:
      name: memory
      target:
        type: AverageValue                     # % 가 아니라 절대값
        averageValue: 5Mi                      # Pod 당 평균 5Mi 를 유지하도록
```

Service(`stateless-svc2`, nodePort 30002)도 함께 만든다.

## 실습 과정

### 1. 만들자마자 목표를 넘어 있다

```bash
clear                                                           # 화면 정리 후 시작
kubectl apply -f - <<'END'                                      # Deployment, Service, HPA 생성
# ... 위 YAML 전체 ...
END

kubectl rollout status deploy/stateless-memory1 --timeout=240s  # Pod 대기
kubectl get hpa                                                 # 현재 값
kubectl top pod -l resource=memory                              # 실제 사용량
```

```
NAME                  REFERENCE                      TARGETS       MINPODS   MAXPODS   REPLICAS
hpa-resource-memory   Deployment/stateless-memory1   9582592/5Mi   2         10        2

NAME                                 CPU(cores)   MEMORY(bytes)
stateless-memory1-7cc498dcf5-8h76n   1m           9Mi
stateless-memory1-7cc498dcf5-8zmq5   0m           9Mi
```

**부하를 주지 않았는데 이미 목표를 넘었다.**
`9582592` 바이트 = 약 9.1Mi 인데 목표는 5Mi다.

JVM이든 Node.js든 **떠 있기만 해도 쓰는 기본 메모리**가 있기 때문이다.
목표를 5Mi로 잡은 것이 애초에 실제 사용량보다 작았다.

### 2. 계속 늘어난다

```bash
clear  # 화면 정리 후 시작
for i in $(seq 1 10); do
  printf "  [%3ds] %s\n" $((i*15)) "$(kubectl get hpa hpa-resource-memory --no-headers | awk '{print "TARGETS="$3"  REPLICAS="$6}')"
  timeout 15 tail -f /dev/null
done
```

```
  [ 15s] TARGETS=9586688/5Mi     REPLICAS=4
  [ 90s] TARGETS=9534976/5Mi     REPLICAS=8
  [105s] TARGETS=9100800/5Mi     REPLICAS=10     ← maxReplicas 도달
  [150s] TARGETS=9435545600m/5Mi REPLICAS=10     ← 그대로 멈춰 있다
```

**2 → 4 → 8 → 10.** 그리고 10에서 멈췄다. 부하를 준 적이 없는데도.

### 검증: 왜 줄어들지 않는가

CPU 때와 결정적으로 다르다.

```
[CPU]     Pod 을 늘리면 → 요청이 나뉘어 → Pod 당 CPU 사용률이 내려간다 → 목표 도달
[메모리]  Pod 을 늘려도 → 각 Pod 이 여전히 9Mi 를 쓴다 → 평균은 그대로 9Mi
```

**Pod을 늘려도 평균이 안 내려간다.** HPA는 "아직 목표보다 높네" 하며 계속 늘리고,
`maxReplicas` 에 닿아서야 멈춘다.

부하와 무관하게 **처음부터 10개로 뜬 것과 같은 상태**다. 자동 확장의 의미가 없다.

> **이것이 메모리 기반 HPA의 함정이다.**
> - 메모리는 **부하에 비례해 늘었다 줄었다 하지 않는다.** 한 번 잡으면 잘 안 놓는다.
> - 목표값을 **실제 사용량보다 낮게** 잡으면 무조건 max까지 간다.
> - 반대로 너무 높게 잡으면 영원히 안 늘어난다.
>
> 그래서 실무에서는 **CPU 기반 HPA가 기본**이고, 메모리는
> "메모리를 쓰면 쓸수록 처리량이 느는" 구조일 때만 제한적으로 쓴다.

목표값을 실제보다 크게(예: `15Mi`) 잡으면 2개를 유지한다.
**측정을 먼저 하고 목표를 정해야 한다.**

```bash
clear                               # 화면 정리 후 시작
kubectl top pod -l resource=memory  # 실제 사용량을 먼저 본다
# 그 값보다 여유 있게 averageValue 를 잡는다
```

## 배운 것

- `AverageValue` 는 **Pod당 평균 절대값**을 목표로 한다. `%` 가 아니다.
- 표시가 `9582592/5Mi` 처럼 **바이트/목표** 형태로 나온다.
- **메모리는 Pod을 늘려도 평균이 안 내려간다.** 목표가 실사용보다 낮으면 max까지 직행한다.
- 목표값은 **`kubectl top` 으로 실측한 뒤** 정해야 한다.
- 실무에서는 **CPU 기반이 기본**이다. 메모리 기반은 신중히.
