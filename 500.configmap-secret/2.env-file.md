# 2) Env (File) — 파일 내용을 환경변수로 주입

원문 : https://cafe.naver.com/kubeops/500 (2. Env (File))

yaml에 값을 직접 적는 대신 **파일에서 읽어** ConfigMap/Secret을 만든다.
설정 파일이 이미 있을 때 쓴다.

## 왜 필요한가

### 없으면 이렇게 된다

[1. Env (Literal)](1.env-literal.md)은 값을 YAML에 **직접 타이핑**한다.
값이 두세 개일 때는 괜찮지만, 이미 설정 파일이 있는 경우에는 곤란해진다.

기존 `application.properties`에 항목이 30개 있다면 그걸 전부 YAML로 옮겨 적어야 하고,
파일이 바뀔 때마다 다시 옮겨야 한다. **원본과 YAML 두 벌을 관리**하게 된다.

### 파일에서 읽어 만드는 방식

`--from-file`은 **이미 있는 파일을 그대로 ConfigMap으로 만든다.**

```
기존 설정 파일  ──kubectl create --from-file──▶  ConfigMap
  (그대로 둔다)                                   (파일 이름이 key)
```

여기서 두 번째 문제가 드러난다. 파일 이름이 그대로 key가 되므로
`application.properties`처럼 **점이 든 이름**이 key가 된다.
환경변수 이름에 점은 쓰기 곤란하다. 그래서 key를 골라 **이름을 바꿔 주입하는 방법**이
따로 필요하고, 그것이 `env[].valueFrom`이다.

| 방식 | 가져오는 것 | 이름 |
|---|---|---|
| `envFrom` | **전부** | key 이름 그대로 |
| `env[].valueFrom` | **고른 것만** | 원하는 이름으로 |

### 이 문서에서 확인할 것

- `--from-file`로 만들면 key가 무엇이 되는가 (1절)
- `kubectl create secret`은 base64를 직접 해야 하는가 (2절)
- key 이름을 바꿔서 주입하려면 어떻게 하는가 (3절)

## 실습 시작 전 정리

```bash
clear                       # 화면 정리 후 시작

# default 네임스페이스의 실습 리소스를 전부 삭제 (시스템 네임스페이스는 건드리지 않는다)
kubectl delete pod,deploy,rs,statefulset,daemonset,job,cronjob \
  --all -n default --grace-period=1 --ignore-not-found

# Service는 kubernetes(클러스터 기본 서비스)만 남기고 삭제
kubectl delete svc -n default \
  --field-selector 'metadata.name!=kubernetes' --ignore-not-found

# ConfigMap·Secret도 비운다 (kube-root-ca.crt는 시스템이 만든 것이라 제외)
kubectl delete cm -n default \
  --field-selector 'metadata.name!=kube-root-ca.crt' --ignore-not-found
kubectl delete secret --all -n default --ignore-not-found

kubectl get all -n default  # service/kubernetes 만 남으면 정상
```

> **`-n default`를 반드시 붙인다.** `-A`(전 네임스페이스)로 실행하면 `kube-system`,
> `calico-system` 등 클러스터 구동에 필요한 리소스까지 지워져 **클러스터가 망가진다.**

## 만드는 명령

```bash
clear                                                            # 화면 정리 후 시작
echo "Content" > file-c.txt                                      # ConfigMap 재료 파일
kubectl create configmap cm-file --from-file=./file-c.txt        # 파일 이름이 key, 내용이 value가 된다

echo "Content" > file-s.txt                                      # Secret 재료 파일
kubectl create secret generic sec-file --from-file=./file-s.txt  # base64는 자동으로 해준다
```

만들어진 결과를 보면 **파일 이름이 그대로 key**가 된다.

```bash
clear                                              # 화면 정리 후 시작
kubectl get cm cm-file -o jsonpath='{.data}'       # ConfigMap 내용
kubectl get secret sec-file -o jsonpath='{.data}'  # Secret 내용
```

```
{"file-c.txt":"Content\n"}
{"file-s.txt":"Q29udGVudAo="}     ← 명령으로 만들면 base64를 알아서 해준다
```

> key를 파일명이 아닌 다른 이름으로 두고 싶으면 `=` 앞에 이름을 적는다.
> ```bash
> kubectl create configmap cm-file --from-file=file=./file-c.txt
> ```
> 그러면 key가 `file-c.txt`가 아니라 `file`이 된다.

## YAML

`envFrom`으로 통째로 가져오는 대신, **key를 골라서 원하는 이름의 환경변수로** 넣는다.

```bash
clear                                          # 화면 정리 후 시작
kubectl apply -f - <<'END'                     # pod-file — Pod
apiVersion: v1
kind: Pod
metadata:
  name: pod-file
spec:
  containers:
  - name: container
    image: kubetm/init
    env:                                       # envFrom 과 달리 하나씩 지정한다
    - name: file-c                             # 환경변수 이름은 내가 정한다
      valueFrom:
        configMapKeyRef:
          name: cm-file                        # 어느 ConfigMap에서
          key: file-c.txt                      # 어느 key를 가져올지
    - name: file-s
      valueFrom:
        secretKeyRef:
          name: sec-file                       # Secret은 secretKeyRef 를 쓴다
          key: file-s.txt
END
```

## 실습 과정

```bash
clear                                                           # 화면 정리 후 시작
kubectl apply -f - <<'END'                                      # Pod 생성 (YAML은 위 절 참고)
# ... 위 YAML 전체 ...
END

kubectl wait --for=condition=Ready pod/pod-file --timeout=120s  # Pod이 뜰 때까지 대기
kubectl exec pod-file -- sh -c 'env | grep -E "^file-"'         # 주입된 환경변수 확인
```

```
file-c=Content
file-s=Content
```

key는 `file-c.txt`인데 환경변수 이름은 `file-c`다. **`env[].name`에 적은 이름이 쓰인다.**

### 검증: envFrom 으로 넣으면 `.txt` 가 제거되는가

원문은 *"Configmap의 key는 file-c.txt가 되지만, 환경변수로 들어갔을 경우 .txt는 허용되지 않기 때문에 제거됨"* 이라고 적고 있다. 확인해봤다.

```bash
clear                                                                   # 화면 정리 후 시작
kubectl apply -f - <<'END'                                              # envFrom 으로 cm-file 을 통째로 넣어본다
apiVersion: v1
kind: Pod
metadata:
  name: pod-envfrom-test
spec:
  containers:
  - name: container
    image: kubetm/init
    envFrom:
    - configMapRef:
        name: cm-file
END

kubectl wait --for=condition=Ready pod/pod-envfrom-test --timeout=120s  # 뜰 때까지 대기
kubectl exec pod-envfrom-test -- sh -c 'env | grep -i file'             # 어떤 이름으로 들어갔나
```

```
file-c.txt=Content
```

**제거되지 않았다.** `.` 이 붙은 그대로 환경변수가 만들어졌다 (k8s v1.27.2 기준).

다만 **셸에서 평범하게 꺼내 쓸 수는 없다.** `$file-c.txt`는 `$file` 뒤에 문자열이 붙은 것으로
해석되기 때문이다. `env`나 `printenv 'file-c.txt'`로만 볼 수 있다.

> 예전 버전에서는 이런 이름을 `InvalidVariableNames` 이벤트와 함께 걸러냈다.
> 지금은 만들어지되 쓰기 불편한 상태로 남는다.
> **결론은 같다** — 파일에서 만든 ConfigMap을 `envFrom`으로 통째로 넣지 말고,
> 위 YAML처럼 `env[].name`으로 이름을 지어주거나 `--from-file=이름=경로`로 key를 정리한다.

### 정리

```bash
clear                                                                    # 화면 정리 후 시작
kubectl delete pod pod-envfrom-test --grace-period=1 --ignore-not-found  # 검증용 Pod만 정리
```

## 배운 것

- `--from-file`로 만들면 **파일 이름이 key**가 된다. `--from-file=이름=경로`로 바꿀 수 있다.
- `kubectl create secret`은 base64를 **자동으로** 해준다. yaml로 직접 쓸 때만 인코딩이 필요하다.
- `env[].valueFrom`은 key를 골라서 **원하는 이름**으로 넣는다.
- `envFrom`은 key 이름을 그대로 쓰므로, key에 `.` 이 있으면 셸에서 쓰기 곤란해진다.
