# 2) Selector — matchLabels와 matchExpressions

원문 : https://cafe.naver.com/kubeops/503 (3. Selector)

컨트롤러가 **어떤 Pod을 자기 것으로 볼지** 정하는 조건.
두 가지 방식을 함께 쓸 수 있고, **모두 만족**해야 선택된다(AND).

| 방식 | 형태 | 표현력 |
|---|---|---|
| `matchLabels` | `key: value` | 정확히 일치하는지만 |
| `matchExpressions` | 조건식 | `In`, `NotIn`, `Exists`, `DoesNotExist` |

## 왜 필요한가

### 없으면 이렇게 된다

[1. Template, Replicas](1.template-replicas.md)에서 봤듯 ReplicaSet은
**selector로 세어서** 개수를 맞춘다. 그러니 selector를 어떻게 쓰느냐가 전부다.

`matchLabels`만으로는 표현이 부족한 때가 있다.
**"dev가 아닌 것 전부"**, **"이 라벨이 붙어 있기만 하면"** 같은 조건은
`key: value` 일치만으로는 쓸 수 없다.

### matchExpressions가 더하는 것

| 방식 | 표현할 수 있는 것 |
|---|---|
| `matchLabels` | 정확히 일치 (`type: web`) |
| `matchExpressions` | `In`, `NotIn`, `Exists`, `DoesNotExist` |

둘을 함께 쓰면 **AND**로 묶인다. 모두 만족해야 선택된다.

여기서 반드시 알아야 할 규칙이 하나 있다.
**`selector`와 `template.labels`가 어긋나면 생성이 거부된다.**

거부하는 이유가 중요하다. 어긋난 채로 허용하면 ReplicaSet이 Pod을 만들고,
만든 Pod이 자기 selector에 안 잡히니 **개수가 여전히 부족하다고 판단해 또 만든다.**
그렇게 **무한히 생성된다.** 그래서 아예 막아 둔 것이다.

### 이 문서에서 확인할 것

- `matchLabels`와 `matchExpressions`를 함께 쓰면 AND인가 OR인가 (2절)
- `Exists`는 `values` 없이 동작하는가 (3절)
- template에 selector보다 라벨이 **많아도** 되는가 (4절)
- 어긋나게 만들면 실제로 어떤 메시지가 나오는가 (검증 절)

## 실습 시작 전 정리

```bash
clear                       # 화면 정리 후 시작

# default 네임스페이스의 실습 리소스를 전부 삭제 (시스템 네임스페이스는 건드리지 않는다)

# Service는 kubernetes(클러스터 기본 서비스)만 남기고 삭제

kubectl get all -n default  # service/kubernetes 만 남으면 정상
```

> `calico-system` 등 클러스터 구동에 필요한 리소스까지 지워져 **클러스터가 망가진다.**

## YAML

```bash
clear                                          # 화면 정리 후 시작
kubectl apply -f - <<'END'                     # replica2 — ReplicaSet (replicas 1)
apiVersion: apps/v1
kind: ReplicaSet
metadata:
  name: replica2
spec:
  replicas: 1
  selector:
    matchLabels:                               # ① 정확히 일치해야 하는 라벨
      type: web
      ver: v1
    matchExpressions:                          # ② 조건식 (①과 AND로 묶인다)
    - {key: type, operator: In, values: [web]} #   type 이 web 중 하나
    - {key: ver, operator: Exists}             #   ver 라는 key 가 있기만 하면 됨
  template:
    metadata:
      labels:
        type: web                              # selector의 모든 조건을 만족해야 한다
        ver: v1
        location: dev                          # selector에 없는 라벨은 더 있어도 된다
    spec:
      containers:
      - name: container
        image: kubetm/app:v1
      terminationGracePeriodSeconds: 0
END
```

### operator 종류

| operator | 뜻 | `values` 필요 |
|---|---|---|
| `In` | key의 값이 목록 안에 있음 | O |
| `NotIn` | key의 값이 목록에 없음 | O |
| `Exists` | key가 존재하기만 하면 됨 | X |
| `DoesNotExist` | key가 없어야 함 | X |

```bash
clear                          # 화면 정리 후 시작
kubectl apply -f - <<'END'     # ReplicaSet 생성 (YAML은 위 절 참고)

END

kubectl get rs replica2        # 개수가 채워졌는지
kubectl get pod --show-labels  # Pod에 붙은 라벨 확인
```

```
NAME       DESIRED   CURRENT   READY
replica2   1         1         0

NAME             READY   LABELS
replica2-8kfzz   0/1     location=dev,type=web,ver=v1
```

`selector`에는 `location`이 없지만 template에는 있다.
**selector의 조건을 만족하기만 하면 라벨이 더 있어도 된다.**

### 검증: selector와 template.labels가 안 맞으면

원문은 *"쿠버네티스가 패치되면서 아래 실습내용과 같은 경우에는 에러가 발생합니다"* 라고 적고 있다.
실제로 확인해봤다.

```bash
clear                       # 화면 정리 후 시작
kubectl apply -f - <<'END'  # selector 는 ver:v2, template 은 ver:v1 (불일치)
apiVersion: apps/v1
kind: ReplicaSet
metadata:
  name: replica-bad
spec:
  replicas: 1
  selector:
    matchLabels:
      type: web
      ver: v2
  template:
    metadata:
      labels:
        type: web
        ver: v1
    spec:
      containers:
      - name: container
        image: kubetm/app:v1
END
```

```
The ReplicaSet "replica-bad" is invalid: spec.template.metadata.labels:
  Invalid value: map[string]string{"type":"web", "ver":"v1"}:
  `selector` does not match template `labels`
```

**생성 자체가 거부된다.** API 서버가 막아준다.

막는 이유는 분명하다. selector가 template의 라벨과 다르면 이런 일이 벌어진다.

```
ReplicaSet: "ver=v2 인 Pod이 1개 필요해"
  → 없네? 만들자 → template대로 ver=v1 Pod 생성
  → 다시 확인: "ver=v2 인 Pod이 여전히 0개네" → 또 만든다
  → 무한 반복
```

Pod이 끝없이 만들어진다. 그래서 **생성 시점에 막는다.**

### 정리

```bash
clear                                                 # 화면 정리 후 시작
kubectl delete rs \
  replica1 \
  replica2 \
  --grace-period=1 --ignore-not-found

kubectl delete pod --all -n default --grace-period=1  # orphan 으로 남은 Pod까지 정리
```

## 배운 것

- `matchLabels`와 `matchExpressions`는 **AND**로 묶인다. 둘 다 만족해야 한다.
- `Exists`/`DoesNotExist`는 `values` 없이 key 존재 여부만 본다.
- template에는 selector에 없는 라벨이 **더 있어도 된다.**
- `selector`와 `template.labels`가 어긋나면 **생성이 거부된다.**
  허용하면 Pod이 무한히 생성되기 때문이다.
