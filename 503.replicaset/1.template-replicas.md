# 1) Template, Replicas — Pod을 원하는 개수만큼 유지하기

원문 : https://cafe.naver.com/kubeops/503 (1. Template, 2. Replicas)

ReplicaSet은 **"이 모양의 Pod을 N개 유지해라"** 는 컨트롤러다.

- **Template** : 찍어낼 Pod의 설계도
- **Replicas** : 유지할 개수

> 실무에서 ReplicaSet을 직접 만들 일은 거의 없다. Deployment가 대신 만들어준다(게시글 504).
> 여기서는 **동작 원리를 보기 위해** 직접 다룬다.

## 왜 필요한가

### 없으면 이렇게 된다

Pod을 직접 만들면 **그걸로 끝이다.** 죽어도 아무도 되살리지 않는다.
트래픽이 늘어 3개로 늘리려면 YAML을 세 벌 만들어야 하고, 줄일 때는 하나씩 지워야 한다.

[497 1-2](../497.pod-container-label-nodeschedule/1-2.deployment.md)에서 Deployment가
Pod을 되살리는 것을 봤다. **실제로 그 일을 하는 것은 Deployment가 아니라 ReplicaSet**이다.

### ReplicaSet이 맡는 일

ReplicaSet의 일은 하나다. **"이 모양의 Pod이 지금 몇 개인지 세어서 N개에 맞춘다."**

| 구성 | 뜻 |
|---|---|
| **Template** | 찍어낼 Pod의 설계도 |
| **Replicas** | 유지할 개수 |
| **Selector** | **무엇을 자기 것으로 셀지** — [2. Selector](2.selector.md) |

세 번째가 핵심이다. ReplicaSet은 자기가 만든 Pod을 기억하지 않는다.
**매번 selector로 세어 본다.** 그래서 조건에 맞는 Pod이 이미 있으면 **그것을 인수**하고,
그만큼 덜 만든다. 이 성질이 있어야 Deployment의 롤링 업데이트가 가능해진다.

> 실무에서 ReplicaSet을 직접 만들 일은 거의 없다. Deployment가 대신 만들어준다.
> 여기서 직접 다루는 이유는 **그 아래에서 벌어지는 일을 보기 위해서**다.

### 이 문서에서 확인할 것

- `replicas`를 늘리고 줄이면 Pod이 어떻게 되는가 (2절)
- Pod을 지우면 **같은 이름**으로 돌아오는가 (3절)
- 조건에 맞는 Pod이 미리 있으면 ReplicaSet은 어떻게 하는가 (4절)
- 컨트롤러만 지우고 Pod을 남길 수 있는가 (5절)

## 실습 시작 전 정리

```bash
clear                       # 화면 정리 후 시작

# default 네임스페이스의 실습 리소스를 전부 삭제 (시스템 네임스페이스는 건드리지 않는다)
kubectl delete pod,deploy,rs,statefulset,daemonset,job,cronjob \
  --all -n default --grace-period=1 --ignore-not-found

# Service는 kubernetes(클러스터 기본 서비스)만 남기고 삭제
kubectl delete svc -n default \
  --field-selector 'metadata.name!=kubernetes' --ignore-not-found

kubectl get all -n default  # service/kubernetes 만 남으면 정상
```

> **`-n default`를 반드시 붙인다.** `-A`(전 네임스페이스)로 실행하면 `kube-system`,
> `calico-system` 등 클러스터 구동에 필요한 리소스까지 지워져 **클러스터가 망가진다.**

## YAML

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: pod1
  labels:
    type: web                                  # 이 라벨이 아래 ReplicaSet의 selector와 맞는다
spec:
  containers:
  - name: container
    image: kubetm/app:v1
  terminationGracePeriodSeconds: 0             # 실습용 — 삭제를 기다리지 않고 즉시 죽인다
---
apiVersion: apps/v1
kind: ReplicaSet                               # apps 그룹
metadata:
  name: replica1
spec:
  replicas: 1                                  # 유지할 Pod 개수
  selector:                                    # 어떤 Pod을 "내 것"으로 볼지
    matchLabels:
      type: web
  template:                                    # 개수가 모자랄 때 찍어낼 설계도
    metadata:
      labels:
        type: web                              # selector와 반드시 일치해야 한다
    spec:
      containers:
      - name: container
        image: kubetm/app:v1
      terminationGracePeriodSeconds: 0
```

## 실습 과정

### 1. 이미 있는 Pod을 ReplicaSet이 인수한다

먼저 **단독 Pod**을 만든다.

```bash
clear                                                           # 화면 정리 후 시작
kubectl apply -f - <<'END'                                      # 단독 Pod 먼저 생성
# ... pod1 YAML ...
END

kubectl wait --for=condition=Ready pod/pod1 --timeout=120s      # 뜰 때까지 대기
kubectl get pod pod1 -o jsonpath='{.metadata.ownerReferences}'  # 소유자가 있는가
```

```
(빈 값 — 소유자 없음)
```

이제 **같은 라벨을 selector로 갖는 ReplicaSet**을 만든다.

```bash
clear                                                                                                       # 화면 정리 후 시작
kubectl apply -f - <<'END'                                                                                  # replicas=1 인 ReplicaSet 생성
# ... replica1 YAML ...
END

kubectl get rs,pod                                                                                          # Pod이 새로 생겼는지
kubectl get pod pod1 -o jsonpath='{.metadata.ownerReferences[0].kind}/{.metadata.ownerReferences[0].name}'  # pod1 의 소유자
```

```
NAME                       DESIRED   CURRENT   READY
replicaset.apps/replica1   1         0         0

NAME       READY   STATUS    AGE
pod/pod1   1/1     Running   5s        ← 새 Pod을 만들지 않았다

pod1 의 소유자: ReplicaSet/replica1
```

**새 Pod을 만들지 않고 기존 `pod1`을 자기 것으로 삼았다.**
selector에 맞는 Pod이 이미 1개 있으니 개수가 채워진 것이다.

> ReplicaSet은 Pod을 "만드는" 게 아니라 **개수를 맞추는** 컨트롤러다.
> 모자라면 만들고, 이미 있으면 그냥 가져간다.

### 2. Replicas를 늘리면

```bash
clear                                                              # 화면 정리 후 시작
kubectl scale --replicas=2 replicaset replica1                     # 개수를 2로 변경
kubectl wait --for=condition=Ready pod -l type=web --timeout=120s  # 새 Pod이 뜰 때까지
kubectl get pod                                                    # 이름이 어떻게 붙었는지
```

```
NAME                 READY   STATUS    AGE
pod/pod1             1/1     Running   23s      ← 내가 지은 이름
pod/replica1-64lxb   1/1     Running   4s       ← 컨트롤러가 지은 이름
```

컨트롤러가 만든 Pod은 `<ReplicaSet이름>-<랜덤5자>` 형태다.
같은 ReplicaSet 아래에 **내가 지은 이름과 컨트롤러가 지은 이름이 섞여 있다.**

### 3. Pod을 지우면 이름이 돌아오지 않는다

```bash
clear                                                              # 화면 정리 후 시작
kubectl delete pod pod1 --grace-period=1                           # 내가 만든 Pod을 삭제
kubectl wait --for=condition=Ready pod -l type=web --timeout=120s  # 대체 Pod 대기
kubectl get pod -l type=web                                        # 어떤 이름으로 살아났나
```

```
NAME             READY   STATUS    AGE
replica1-64lxb   1/1     Running   6s
replica1-brfxv   1/1     Running   2s        ← pod1 이 아니라 랜덤 이름
```

**`pod1`이라는 이름은 사라졌다.** ReplicaSet은 개수만 맞출 뿐
어떤 이름의 Pod이었는지는 기억하지 않는다.

> 그래서 "특정 이름을 계속 유지해야 하는" 워크로드에는 ReplicaSet이 맞지 않는다.
> 그런 경우가 StatefulSet이다 (게시글 528).

### 4. 컨트롤러만 지우고 Pod은 남기기

```bash
clear                                                                                                                         # 화면 정리 후 시작
kubectl delete replicaset replica1 --cascade=orphan                                                                           # Pod은 남기고 ReplicaSet만 삭제
kubectl get rs,pod                                                                                                            # 무엇이 남았나
kubectl get pod -l type=web -o jsonpath='{range .items[*]}{.metadata.name}{" owner="}{.metadata.ownerReferences}{"\n"}{end}'  # 소유자 확인
```

```
replicaset.apps "replica1" deleted

NAME                 READY   STATUS    AGE
pod/replica1-64lxb   1/1     Running   17s
pod/replica1-brfxv   1/1     Running   13s

replica1-64lxb owner=        ← 소유자가 사라졌다
replica1-brfxv owner=
```

Pod은 살아남고 **소유 관계만 끊겼다.** 이제 이 Pod들은 단독 Pod이라
지워도 다시 살아나지 않는다.

`--cascade=orphan`을 안 붙이면 ReplicaSet과 함께 Pod도 전부 지워진다(기본 동작).

## 배운 것

- ReplicaSet은 **개수를 맞추는** 컨트롤러다. selector에 맞는 Pod이 있으면 인수한다.
- 컨트롤러가 만드는 Pod 이름은 `<RS이름>-<랜덤5자>` 다.
- Pod을 지우면 대체 Pod이 생기지만 **이름은 복원되지 않는다.**
- `--cascade=orphan` 으로 컨트롤러만 지우고 Pod을 남길 수 있다.
- `template.labels`는 `selector`와 반드시 일치해야 한다 ([selector 문서](2.selector.md) 참고).
