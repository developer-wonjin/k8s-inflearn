# 2) kubectl — 여러 클러스터를 오가기

원문 : https://cafe.naver.com/kubeops/522 (2. kubectl)

> ## 이 절은 실습하지 않았다
>
> **두 번째 클러스터(cluster-B)가 필요하다.** 원문도 *"해당 실습을 진행해보시려면
> 클러스터(cluster-B)를 하나 더 설치하셔야 합니다"* 라고 안내한다.
>
> 이 환경에는 클러스터가 하나뿐이라 개념과 명령만 정리한다.
> 실제로 해보려면 아래 [두 번째 클러스터 만들기](#두-번째-클러스터-만들기)를 참고한다.

## kubeconfig의 구조

한 파일에 **여러 클러스터**를 담을 수 있다. 세 덩어리가 서로를 참조한다.

```
clusters   : 어디에 접속하나   (주소 + CA 인증서)
users      : 누구로 접속하나   (클라이언트 인증서 + 키)
contexts   : 위 둘의 조합       ← kubectl 은 이걸 하나 골라서 쓴다
```

```yaml
apiVersion: v1
kind: Config
clusters:
- cluster:
    certificate-authority-data: LS0tLS1...      # cluster-a 의 CA
    server: https://192.168.0.30:6443
  name: cluster-a
- cluster:
    certificate-authority-data: LS0tLS1...      # cluster-b 의 CA
    server: https://192.168.0.50:6443
  name: cluster-b
contexts:
- context:
    cluster: cluster-a                          # 이 클러스터에
    user: admin-a                               # 이 사용자로
  name: context-a                               # 붙인 이름
- context:
    cluster: cluster-b
    user: admin-b
  name: context-b
current-context: context-a                      # 지금 쓰는 조합
users:
- name: admin-a
  user:
    client-certificate-data: LS0tLS1...
    client-key-data: LS0tLS1...
- name: admin-b
  user:
    client-certificate-data: LS0tLS1...
    client-key-data: LS0tLS1...
```

각 클러스터의 `/etc/kubernetes/admin.conf` 내용을 이 형식으로 합치면 된다.

## 컨텍스트 전환

```bash
clear                                 # 화면 정리 후 시작
kubectl config get-contexts           # 등록된 컨텍스트 목록
kubectl config current-context        # 지금 어디에 붙어 있나
kubectl config use-context context-b  # cluster-b 로 전환
kubectl get nodes                     # 이제 cluster-b 의 노드가 보인다
```

이 클러스터에서 실행하면 이렇게 나온다.

```
CURRENT   NAME                          CLUSTER      AUTHINFO
*         kubernetes-admin@kubernetes   kubernetes   kubernetes-admin
```

컨텍스트가 하나뿐이라 전환할 대상이 없다.

## 알아두면 좋은 명령

```bash
clear                                                   # 화면 정리 후 시작
kubectl config view                                     # 현재 kubeconfig 내용 (인증서는 가려져서 나온다)
kubectl config view --raw                               # 인증서까지 전부 (다룰 때 주의)
kubectl config set-context --current --namespace=nm-01  # 기본 네임스페이스 변경
kubectl config get-contexts                             # 바뀐 결과 확인
```

`--namespace` 를 컨텍스트에 박아두면 매 명령에 `-n` 을 안 붙여도 된다.
네임스페이스를 자주 오갈 때 유용하다.

## 두 번째 클러스터 만들기

원문이 안내하는 방법이다. **PC(호스트)에서** 실행한다.

```bash
clear       # 화면 정리 후 시작
mkdir k8s2  # 새 디렉토리
cd k8s2     # 이동
curl -O https://raw.githubusercontent.com/k8s-1pro/install/main/ground/k8s-1.27/vagrant-2.4.3-slim/Vagrantfile
vagrant up  # 두 번째 클러스터 기동
```

실습 후에는 `vagrant destroy` 로 정리한다.

> 이 저장소의 클러스터도 Vagrant로 만든 것이다.
> 프로젝트 루트의 `Vagrantfile`이 그것이다.
> 두 번째 클러스터는 **IP 대역이 겹치지 않게** 해야 한다.

## 배운 것 (개념)

- kubeconfig 하나에 **여러 클러스터·사용자·컨텍스트**를 담을 수 있다.
- `context` = `cluster` + `user` 의 조합에 붙인 이름이다.
- `kubectl config use-context` 로 클러스터를 갈아탄다.
- 컨텍스트에 기본 네임스페이스를 지정해두면 `-n` 을 생략할 수 있다.
- `kubectl config view --raw` 에는 **인증서 원본이 그대로** 들어 있다. 공유 금지.
