# 1) Recreate — 다 내리고 다시 올리기

원문 : https://cafe.naver.com/kubeops/504 (1. ReCreate)

기존 Pod을 **전부 지운 뒤** 새 Pod을 올린다.
그 사이에는 응답할 Pod이 하나도 없다 → **다운타임 발생**.

## 실습 시작 전 정리

```bash
clear                       # 화면 정리 후 시작

# default 네임스페이스의 실습 리소스를 전부 삭제 (시스템 네임스페이스는 건드리지 않는다)
kubectl delete pod,deploy,rs,statefulset,daemonset,job,cronjob \
  --all -n default --grace-period=1 --ignore-not-found

# Service는 kubernetes(클러스터 기본 서비스)만 남기고 삭제
kubectl delete svc -n default \
  --field-selector 'metadata.name!=kubernetes' --ignore-not-found

kubectl get all -n default  # service/kubernetes 만 남으면 정상
```

> **`-n default`를 반드시 붙인다.** `-A`(전 네임스페이스)로 실행하면 `kube-system`,
> `calico-system` 등 클러스터 구동에 필요한 리소스까지 지워져 **클러스터가 망가진다.**

## YAML

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: deployment-1
spec:
  selector:
    matchLabels:
      type: app
  replicas: 2
  strategy:
    type: Recreate                             # 기존을 다 내린 뒤 새로 올린다
  revisionHistoryLimit: 1                      # 롤백용 옛 ReplicaSet을 1개만 보관
  template:
    metadata:
      labels:
        type: app
    spec:
      containers:
      - name: container
        image: kubetm/app:v1                   # /version 으로 버전을 응답하는 이미지
      terminationGracePeriodSeconds: 10
---
apiVersion: v1
kind: Service
metadata:
  name: svc-1
spec:
  selector:
    type: app
  ports:
  - port: 8080
    protocol: TCP
    targetPort: 8080
```

## 실습 과정

### 1. 생성

```bash
clear                                                        # 화면 정리 후 시작
kubectl apply -f - <<'END'                                   # Deployment와 Service 생성 (YAML은 위 절 참고)
# ... 위 YAML 전체 ...
END

kubectl rollout status deploy/deployment-1 --timeout=180s    # 롤아웃 완료까지 대기
IP=$(kubectl get svc svc-1 -o jsonpath='{.spec.clusterIP}')  # Service IP를 변수에
curl $IP:8080/version                                        # 현재 버전 확인
```

```
Version : v1
```

### 2. v2로 올리면서 1초 간격으로 호출한다

업그레이드 도중 서비스가 끊기는지 보려면 **계속 호출하면서** 이미지를 바꿔야 한다.

```bash
clear                     # 화면 정리 후 시작
# 백그라운드에서 1초 간격으로 40번 호출하며 로그를 남긴다
( for i in $(seq 1 40); do
    r=$(curl -s --max-time 1 $IP:8080/version 2>/dev/null)
    printf "  [%2ds] %s\n" $i "${r:-*** 응답 없음 (다운타임) ***}"
    timeout 1 tail -f /dev/null
  done ) > recreate.log 2>&1 &

# 몇 초 뒤 이미지를 바꾼다
kubectl set image deployment deployment-1 container=kubetm/app:v2

wait                      # 백그라운드 루프가 끝날 때까지
uniq -c -f1 recreate.log  # 연속된 같은 응답을 묶어서 본다
```

```
      1   [ 1s] Version : v1
      ...
      4   [10s] Version : v1
      2   [14s] *** 응답 없음 (다운타임) ***
     25   [16s] Version : v2
```

**약 2초 동안 아무 응답도 못 받았다.**

```
v1 v1 v1 ... v1 │ (없음) (없음) │ v2 v2 v2 ...
                └── 다운타임 ──┘
```

기존 Pod 2개를 모두 종료한 뒤에야 새 Pod을 만들기 때문이다.

### 3. ReplicaSet은 이렇게 바뀐다

```bash
clear                       # 화면 정리 후 시작
kubectl get rs -l type=app  # 옛 RS와 새 RS
```

```
NAME                      DESIRED   CURRENT   READY   AGE
deployment-1-79fb6f4964   2         2         2       73s      ← 새 RS (v2)
deployment-1-984655d99    0         0         0       88s      ← 옛 RS (v1), 0으로 내려감
```

Deployment는 RS를 **고치지 않는다.** 새 RS를 만들고 옛 RS를 0으로 내린다.
옛 RS는 삭제되지 않고 남아 있어 롤백에 쓰인다.

### 검증: `--to-revision=1` 로 롤백이 되는가

원문은 `kubectl rollout undo deployment deployment-1 --to-revision=1` 을 안내한다.
그대로 해봤다.

```bash
clear                                                         # 화면 정리 후 시작
kubectl rollout history deployment deployment-1               # 남아 있는 리비전 확인
kubectl rollout undo deployment deployment-1 --to-revision=1  # 1번으로 롤백 시도
```

```
REVISION  CHANGE-CAUSE
3         <none>
4         <none>

error: unable to find specified revision 1 in history
```

**실패한다.** 리비전 1이 목록에 없기 때문이다.

원인은 yaml에 적힌 `revisionHistoryLimit: 1` 이다.
**옛 ReplicaSet을 1개만 보관**하므로 그보다 오래된 리비전은 지워진다.
남은 것은 3, 4번뿐이다.

`--to-revision` 없이 쓰면 **직전 리비전**으로 돌아가므로 잘 동작한다.

```bash
clear                                                      # 화면 정리 후 시작
kubectl rollout undo deployment deployment-1               # 직전 리비전으로 롤백
kubectl rollout status deploy/deployment-1 --timeout=180s  # 완료까지 대기
curl $IP:8080/version                                      # 버전 확인
```

```
deployment.apps/deployment-1 rolled back
Version : v1
```

> **리비전 번호는 재사용되지 않고 계속 증가한다.** 롤백해도 "1번으로 되돌아간" 게 아니라
> "1번과 같은 내용의 5번"이 새로 생긴다.
> `revisionHistoryLimit`을 작게 두면 그만큼 되돌릴 수 있는 지점이 줄어든다.
> 기본값은 10이다.

### 정리

```bash
clear                                                                   # 화면 정리 후 시작
kubectl delete deploy deployment-1 --grace-period=1 --ignore-not-found  # Deployment 삭제
kubectl delete svc svc-1 --ignore-not-found                             # Service 삭제
```

## 배운 것

- `Recreate`는 **전부 내린 뒤 올린다.** 실측 약 2초의 다운타임이 있었다.
- 대신 **추가 자원이 필요 없다.** 옛 버전과 새 버전이 동시에 뜨지 않기 때문이다.
- Deployment는 RS를 고치지 않고 **새 RS를 만들어 옮겨 담는다.**
- `revisionHistoryLimit`은 되돌릴 수 있는 지점의 개수다. 작게 두면 `--to-revision`이 실패한다.
- 리비전 번호는 재사용되지 않는다.
