# 2) Job — 한 번 하고 끝나는 작업

원문 : https://cafe.naver.com/kubeops/507 (2. Job)

Deployment는 Pod이 **계속 떠 있기를** 원한다. 죽으면 되살린다.
Job은 반대다. **작업을 마치고 끝나는 것**이 정상이다.

배치 처리, 마이그레이션, 일회성 스크립트가 이 형태다.

## 왜 필요한가

### 없으면 이렇게 된다

지금까지 다룬 컨트롤러는 전부 **Pod이 계속 떠 있기를** 원한다.
Pod이 종료되면 문제로 보고 되살린다.

그런데 세상에는 **끝나야 하는 작업**이 있다. 데이터 마이그레이션, 야간 배치,
일회성 스크립트 같은 것들이다. 이걸 Deployment로 돌리면 어떻게 될까.

작업이 끝나 컨테이너가 종료되면 → 컨트롤러가 **비정상으로 판단하고 다시 띄운다** →
같은 작업이 **무한히 반복된다.** `CrashLoopBackOff`로 보이지만 사실은 성공한 것이다.

### Job이 뒤집는 것

Job은 **끝나는 것이 정상**이라고 본다. 완료를 기다렸다가 완료되면 그대로 둔다.

| | Deployment | Job |
|---|---|---|
| 원하는 상태 | **계속 실행 중** | **완료됨** |
| 종료되면 | 되살린다 | **정상으로 본다** |
| `restartPolicy` | `Always` | `Never` / `OnFailure` |

완료된 Pod을 지우지 않고 `Completed`로 남겨두는 것도 의도된 동작이다.
**로그를 봐야 하기 때문**이다. 대신 쌓이므로 정리는 직접 하거나
`ttlSecondsAfterFinished`로 자동화한다.

몇 번 실행할지(`completions`), 동시에 몇 개(`parallelism`),
얼마나 기다릴지(`activeDeadlineSeconds`)를 정할 수 있다.

### 이 문서에서 확인할 것

- 작업이 끝난 Pod은 어떤 상태로 남는가 (2절)
- `completions`와 `parallelism`을 주면 실행 순서가 어떻게 되는가 (3절)
- 제한 시간을 넘기면 **이미 완료된 것까지** 사라지는가 (4절)

## 실습 시작 전 정리

```bash
clear                       # 화면 정리 후 시작

# default 네임스페이스의 실습 리소스를 전부 삭제 (시스템 네임스페이스는 건드리지 않는다)
kubectl delete pod,deploy,rs,statefulset,daemonset,job,cronjob \
  --all -n default --grace-period=1 --ignore-not-found

# Service는 kubernetes(클러스터 기본 서비스)만 남기고 삭제
kubectl delete svc -n default \
  --field-selector 'metadata.name!=kubernetes' --ignore-not-found

kubectl get all -n default  # service/kubernetes 만 남으면 정상
```

> **`-n default`를 반드시 붙인다.** `-A`(전 네임스페이스)로 실행하면 `kube-system`,
> `calico-system` 등 클러스터 구동에 필요한 리소스까지 지워져 **클러스터가 망가진다.**

## YAML

```yaml
apiVersion: batch/v1                           # batch 그룹 (apps 가 아니다)
kind: Job
metadata:
  name: job-1
spec:
  template:
    spec:
      restartPolicy: Never                     # Job에서는 Always 를 쓸 수 없다
      containers:
      - name: container
        image: kubetm/init
        command: ["sh", "-c", "echo 'job start';sleep 20; echo 'job end'"]
      terminationGracePeriodSeconds: 0
```

`restartPolicy`는 `Never` 또는 `OnFailure`만 쓸 수 있다.
`Always`(Pod의 기본값)로 두면 끝나자마자 다시 살아나 영원히 안 끝나기 때문이다.

## 실습 과정

### 1. 작업이 끝나면 어떻게 되는가

```bash
clear                       # 화면 정리 후 시작
kubectl apply -f - <<'END'  # Job 생성 (YAML은 위 절 참고)
# ... 위 YAML 전체 ...
END

kubectl get pod -w          # 상태 변화를 지켜본다
```

```
job-1-cv8fk   0/1   Pending             0s
job-1-cv8fk   0/1   ContainerCreating   0s
job-1-cv8fk   1/1   Running             2s
job-1-cv8fk   0/1   Completed           24s      ← 종료 상태로 남는다
```

```bash
clear                           # 화면 정리 후 시작
kubectl get job,pod             # Job과 Pod의 최종 상태
kubectl logs -l job-name=job-1  # 완료된 Pod의 로그
```

```
job.batch/job-1   COMPLETIONS 1/1   DURATION 24s

pod/job-1-cv8fk   0/1   Completed

job start
job end
```

**Pod이 삭제되지 않고 `Completed`로 남는다.**
로그를 나중에 확인할 수 있게 하기 위해서다. 정리는 사용자 몫이다.

> 자동으로 지우려면 `spec.ttlSecondsAfterFinished`를 쓴다.
> 예를 들어 `ttlSecondsAfterFinished: 300`이면 완료 5분 뒤 Job과 Pod이 사라진다.

### 2. 여러 개를, 몇 개씩, 제한 시간 안에

```yaml
apiVersion: batch/v1
kind: Job
metadata:
  name: job-2
spec:
  completions: 6                               # 총 6개를 성공시켜야 끝난다
  parallelism: 2                               # 동시에는 2개까지만 돌린다
  activeDeadlineSeconds: 40                    # 40초 안에 못 끝내면 중단한다
  template:
    spec:
      restartPolicy: Never
      containers:
      - name: container
        image: kubetm/init
        command: ["sh", "-c", "echo 'job start';sleep 20; echo 'job end'"]
      terminationGracePeriodSeconds: 0
```

한 번 실행에 20초가 걸리는 작업을 2개씩 6번 = 최소 60초가 필요한데,
제한 시간은 40초다. **일부러 못 끝내게 만든 설정이다.**

```bash
clear                       # 화면 정리 후 시작
kubectl apply -f - <<'END'  # Job 생성
# ... job-2 YAML ...
END

# 5초 간격으로 진행 상황을 본다
for i in $(seq 1 9); do
  printf "  [%2ds] job=%s  pods=%s\n" $((i*5)) \
    "$(kubectl get job job-2 --no-headers | awk '{print $2}')" \
    "$(kubectl get pod --no-headers | grep -c '^job-2')"
  timeout 5 tail -f /dev/null
done
```

```
  [ 5s] job=0/6  pods=2      ← 2개씩 (parallelism)
  [10s] job=0/6  pods=2
  ...
  [30s] job=2/6  pods=4      ← 2개 완료, 다음 2개 시작 (완료된 Pod도 남아서 4)
  [40s] job=2/6  pods=4
  [45s] job=2/6  pods=2      ← 제한 시간 초과, 실행 중이던 Pod이 삭제됨
```

```bash
clear                                                                                                # 화면 정리 후 시작
kubectl get job job-2                                                                                # 최종 상태
kubectl get job job-2 -o jsonpath='{range .status.conditions[*]}{.type}={.status} ({.reason}){end}'  # 중단 사유
```

```
NAME    COMPLETIONS   DURATION   AGE
job-2   2/6           46s        46s

Failed=True (DeadlineExceeded)
```

정확히 원문이 설명한 대로다.

- `parallelism: 2` — 항상 2개씩만 돌았다
- `activeDeadlineSeconds: 40` — 40초에 중단, **실행 중이던 Pod은 삭제**되고
  **완료된 Pod(2개)만 남았다**
- Job 자체는 `Failed` / `DeadlineExceeded`로 끝났다

### 정리

```bash
clear  # 화면 정리 후 시작
kubectl delete job \
  job-1 \
  job-2 \
  --grace-period=1 --ignore-not-found
```

Job을 지우면 그 Job이 만든 Pod도 함께 사라진다.

## 배운 것

- Job은 **끝나는 것이 정상**이다. `restartPolicy`는 `Never`나 `OnFailure`만 쓴다.
- 완료된 Pod은 `Completed`로 **남는다.** 로그 확인용이며 정리는 직접 해야 한다.
  (`ttlSecondsAfterFinished`로 자동화 가능)
- `completions` 총 개수, `parallelism` 동시 개수, `activeDeadlineSeconds` 제한 시간.
- 제한 시간을 넘기면 **실행 중인 것만 죽고 완료된 것은 남는다.** Job은 `DeadlineExceeded`.
