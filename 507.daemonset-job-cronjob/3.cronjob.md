# 3) CronJob — 정해진 시각마다 Job 만들기

원문 : https://cafe.naver.com/kubeops/507 (3. CronJob)

CronJob은 **직접 Pod을 만들지 않는다.** 시간이 되면 **Job을 만들고**, Job이 Pod을 만든다.

```
CronJob ──시각마다──▶ Job ──▶ Pod
```

DB 백업, 주기적 정리, 예약 발송 같은 반복 작업에 쓴다.

## YAML

```yaml
apiVersion: batch/v1
kind: CronJob
metadata:
  name: cron-job
spec:
  schedule: "*/1 * * * *"                      # 분 시 일 월 요일 — 1분마다
  jobTemplate:                                 # 시간이 되면 이 Job을 만든다
    spec:
      template:                                # Job 안의 Pod 설계도
        spec:
          restartPolicy: Never
          containers:
          - name: container
            image: kubetm/init
            command: ["sh", "-c", "echo 'job start';sleep 20; echo 'job end'"]
          terminationGracePeriodSeconds: 0
```

`template`이 두 겹인 것에 주의한다. `jobTemplate`(Job의 설계도) 안에
`template`(Pod의 설계도)이 들어 있다.

### schedule 읽는 법

```
 ┌───── 분    (0-59)
 │ ┌─── 시    (0-23)
 │ │ ┌─ 일    (1-31)
 │ │ │ ┌─ 월  (1-12)
 │ │ │ │ ┌ 요일 (0-6, 0=일요일)
 * * * * *
```

| 예시 | 뜻 |
|---|---|
| `*/1 * * * *` | 1분마다 |
| `0 3 * * *` | 매일 새벽 3시 |
| `0 0 * * 0` | 매주 일요일 0시 |
| `0 */6 * * *` | 6시간마다 |

## 실습 과정

### 1. 1분마다 Job이 생기는지

```bash
clear                       # 화면 정리 후 시작
kubectl apply -f - <<'END'  # CronJob 생성 (YAML은 위 절 참고)
# ... 위 YAML 전체 ...
END

kubectl get cronjob         # 등록 확인
```

```
NAME       SCHEDULE      SUSPEND   ACTIVE   LAST SCHEDULE   AGE
cron-job   */1 * * * *   False     0        <none>          0s
```

### 2. 수동 실행 (Manual Trigger)

시간을 기다리지 않고 지금 한 번 돌려보고 싶을 때 쓴다.

```bash
clear                                                           # 화면 정리 후 시작
kubectl create job --from=cronjob/cron-job cron-job-manual-001  # CronJob의 템플릿으로 Job 즉시 생성
```

```
job.batch/cron-job-manual-001 created
```

### 3. 2분간 관찰

```bash
clear  # 화면 정리 후 시작
# 15초 간격으로 Job 목록을 본다
for i in $(seq 1 8); do
  printf "  [%3ds] %s\n" $((i*15)) "$(kubectl get job --no-headers | awk '{printf "%s(%s) ", $1, $2}')"
  timeout 15 tail -f /dev/null
done
```

```
  [ 15s] cron-job-manual-001(0/1)
  [ 45s] cron-job-29810239(0/1) cron-job-manual-001(1/1)      ← 자동 생성된 첫 Job
  [ 60s] cron-job-29810239(1/1) cron-job-manual-001(1/1)
  [105s] cron-job-29810239(1/1) cron-job-29810240(0/1) ...    ← 1분 뒤 두 번째
  [120s] cron-job-29810239(1/1) cron-job-29810240(1/1) ...
```

자동으로 만들어진 Job은 `<CronJob이름>-<숫자>` 형태다.
뒤의 숫자는 **예정 시각을 분 단위로 환산한 값**이라 실행할 때마다 1씩 늘어난다.

수동으로 만든 Job(`cron-job-manual-001`)은 그대로 남아 있다.
자동 생성분과 이름 규칙이 다르므로 섞이지 않는다.

### 4. suspend — 일시 정지

```bash
clear                                                           # 화면 정리 후 시작
kubectl patch cronjobs cron-job -p '{"spec":{"suspend":true}}'  # 일시 정지
kubectl get cronjob                                             # SUSPEND 열 확인

# 90초 동안 Job 개수가 늘어나지 않는지 본다
for i in $(seq 1 6); do
  printf "  [%2ds] jobs=%s\n" $((i*15)) "$(kubectl get job --no-headers | wc -l)"
  timeout 15 tail -f /dev/null
done
```

```
NAME       SCHEDULE      SUSPEND   ACTIVE   LAST SCHEDULE   AGE
cron-job   */1 * * * *   True      0        54s             2m10s

  [15s] jobs=3
  [30s] jobs=3
  ...
  [90s] jobs=3          ← 1분이 넘게 지나도 새 Job이 안 생긴다
```

**멈춘다.** 이미 만들어진 Job은 그대로 두고 **새로 만드는 것만** 중단한다.
`{"suspend": false}`로 되돌리면 다시 시작한다.

CronJob을 지우지 않고 잠시 꺼둘 때 쓴다. 배포 중이거나 점검 중일 때 유용하다.

### 정리

```bash
clear                                                 # 화면 정리 후 시작
kubectl delete cronjob cron-job --ignore-not-found    # CronJob 삭제
kubectl delete job --all -n default --grace-period=1  # 남아 있는 Job 전부 삭제
```

CronJob을 지워도 **이미 만들어진 Job은 남는다.** 따로 지워야 한다.

## 배운 것

- CronJob은 Pod이 아니라 **Job을 만든다.** 한 단계가 더 있다.
- yaml에 `template`이 두 겹(`jobTemplate.spec.template`)인 이유가 그것이다.
- 자동 생성 Job의 이름은 `<이름>-<예정시각의 분 단위 값>` 이다.
- `kubectl create job --from=cronjob/<이름>` 으로 즉시 실행할 수 있다.
- `suspend: true`는 **새 Job 생성만** 멈춘다. 기존 Job은 그대로 돈다.
- 완료된 Job은 자동으로 정리되지 않는다
  (`successfulJobsHistoryLimit`, `failedJobsHistoryLimit`으로 개수 조절 가능).
