# 3) Endpoint — Service와 Pod을 잇는 실제 연결고리

원문 : https://cafe.naver.com/kubeops/516 (3~5. Endpoint)

Service의 `selector`는 **조건**일 뿐이다.
그 조건으로 찾아낸 **실제 IP 목록**을 담고 있는 것이 Endpoints다.

```
Service (selector: svc=endpoint)
   ↓ 컨트롤러가 조건에 맞는 Pod을 찾아서
Endpoints (20.100.194.110:8080)      ← 실제 목적지
   ↓
Pod
```

## 시작 전 확인

> **여기서는 정리하지 않는다.** 이 문서는 1에서 만든 **`request-pod`** 가 남아 있어야 성립한다.
> 표준 정리 블록을 돌리면 전제가 사라져 실습 자체가 되지 않는다.

| 상황 | 할 일 |
|---|---|
| 앞 문서를 막 끝내고 이어서 온 경우 | 그대로 진행한다 |
| 처음부터 다시 하는 경우 | [1.dns-clusterip.md](1.dns-clusterip.md) 를 먼저 실습하고 돌아온다 |

```bash
clear                        # 화면 정리 후 시작
kubectl get pod request-pod  # 전제가 남아 있는지 확인 — 없으면 앞 문서부터
```

## 3-1) 자동으로 만들어지는 경우

```yaml
apiVersion: v1
kind: Service
metadata:
  name: endpoint1
spec:
  selector:
    svc: endpoint                              # 이 조건에 맞는 Pod을 찾는다
  ports:
  - port: 8080
```

```bash
clear                                                       # 화면 정리 후 시작
kubectl apply -f - <<'END'                                  # Service와 Pod 생성
# ... endpoint1, pod7 YAML ...
END

kubectl wait --for=condition=Ready pod/pod7 --timeout=180s  # Pod 대기
kubectl describe endpoints endpoint1                        # 자동 생성된 Endpoints
```

```
Name:         endpoint1                        ← Service와 이름이 같다
Namespace:    default
Subsets:
  Addresses:          20.100.194.110
  NotReadyAddresses:  <none>
```

**Service와 같은 이름으로 자동 생성된다.**
`NotReadyAddresses`가 따로 있는 것에 주목한다.
ReadinessProbe에 실패한 Pod은 여기로 들어가 트래픽을 안 받는다 (게시글 510).

## 3-2) 직접 만드는 경우 — selector 없는 Service

`selector`를 **적지 않으면** 쿠버네티스가 Endpoints를 만들지 않는다.
직접 만들어 붙일 수 있다.

```yaml
apiVersion: v1
kind: Service
metadata:
  name: endpoint2
spec:
  ports:                                       # selector 가 없다
  - port: 8080
---
apiVersion: v1
kind: Endpoints                                # 직접 만든다
metadata:
  name: endpoint2                              # Service와 이름이 같아야 연결된다
subsets:
- addresses:
  - ip: 20.100.194.113                         # 목적지 IP를 직접 적는다
  ports:
  - port: 8080
```

```bash
clear                                                       # 화면 정리 후 시작
kubectl apply -f - <<'END'                                  # selector 없는 Service와 Pod 생성
# ... endpoint2 Service, pod9 YAML ...
END

kubectl wait --for=condition=Ready pod/pod9 --timeout=180s  # Pod 대기
POD9=$(kubectl get pod pod9 -o jsonpath='{.status.podIP}')  # Pod IP 확인
kubectl get endpoints endpoint2                             # 아직 없다
```

```
Error from server (NotFound): endpoints "endpoint2" not found
```

`selector`가 없으니 만들어주지 않는다. 직접 만든다.

```bash
clear                                                        # 화면 정리 후 시작
# Pod IP를 넣어 Endpoints를 직접 만든다
kubectl apply -f - <<END
apiVersion: v1
kind: Endpoints
metadata:
  name: endpoint2
subsets:
- addresses:
  - ip: $POD9
  ports:
  - port: 8080
END

kubectl get endpoints endpoint2                              # 연결됐는가
kubectl exec request-pod -- curl -s endpoint2:8080/hostname  # Service 이름으로 호출
```

```
NAME        ENDPOINTS             AGE
endpoint2   20.100.194.113:8080   0s

Hostname : pod9
```

**Service 이름으로 호출했는데 pod9이 응답한다.**
라벨 셀렉터를 전혀 쓰지 않았는데도 연결됐다.

> 이때 heredoc을 `<<END`(따옴표 없이)로 쓴 것에 주의한다.
> `$POD9` 변수를 치환해야 하므로 `<<'END'`(따옴표)를 쓰면 안 된다.

## 3-3) 클러스터 밖의 IP를 붙이기

Endpoints에 적는 IP가 **꼭 Pod일 필요는 없다.**

```bash
clear                                                           # 화면 정리 후 시작
kubectl exec request-pod -- nslookup raw.githubusercontent.com  # 외부 도메인의 IP 확인
```

```
Address: 185.199.110.133
```

이 IP로 Service를 만든다.

```yaml
apiVersion: v1
kind: Service
metadata:
  name: endpoint3
spec:
  ports:
  - port: 443
---
apiVersion: v1
kind: Endpoints
metadata:
  name: endpoint3
subsets:
- addresses:
  - ip: 185.199.110.133                        # 클러스터 밖의 IP
  ports:
  - port: 443
```

```bash
clear                       # 화면 정리 후 시작
kubectl apply -f - <<'END'  # Service와 Endpoints 생성
# ... endpoint3 YAML ...
END

# GitHub는 Host 헤더가 있어야 응답한다
kubectl exec request-pod -- curl -sk -o /dev/null -w 'HTTP %{http_code}' \
  "https://endpoint3/k8s-1pro/install/refs/heads/main/container/daeku/app/app.js" \
  -H "Host: raw.githubusercontent.com"
```

```
HTTP 200
```

**클러스터 안의 이름(`endpoint3`)으로 외부 서버를 부르고 있다.**

이렇게 하면 애플리케이션은 외부 주소를 몰라도 된다.
외부 IP가 바뀌면 **Endpoints만 고치면 되고 Pod은 그대로 둔다.**

> `-k` 는 인증서 검증을 건너뛴다. 인증서는 `raw.githubusercontent.com` 앞으로 발급됐는데
> 우리는 `endpoint3` 라는 이름으로 접속하므로 이름이 안 맞기 때문이다.
> 실무에서 외부 HTTPS를 이런 식으로 붙일 때 늘 걸리는 지점이다.

## 배운 것

- Service의 `selector`는 조건이고, **실제 목적지 목록은 Endpoints**에 있다.
- Service를 만들면 **같은 이름의 Endpoints**가 자동으로 생긴다.
- `selector`가 없으면 자동 생성되지 않는다. **직접 만들어 붙일 수 있다.**
- Endpoints의 IP는 **클러스터 밖이어도 된다.** 외부 서비스를 Service 이름으로 감쌀 수 있다.
- 연결이 안 될 때 `kubectl get endpoints` 를 먼저 본다. 비어 있으면 셀렉터가 잘못된 것이다.
