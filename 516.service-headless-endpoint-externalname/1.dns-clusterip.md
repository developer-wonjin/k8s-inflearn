# 1) ClusterIP와 DNS — 이름으로 부르기

원문 : https://cafe.naver.com/kubeops/516 (1. ClusterIP)

Service를 만들면 **이름이 곧 도메인**이 된다.
클러스터에 설치된 CoreDNS가 그 이름을 Service IP로 바꿔준다.

## 왜 필요한가

### 없으면 이렇게 된다

[498 1](../498.service-clusterip-nodeport-loadbalancer/1.clusterip.md)에서 Service가
**고정된 IP**를 준다는 것을 확인했다. Pod IP와 달리 바뀌지 않는다.

그런데 IP를 설정 파일에 적는 것은 여전히 불편하다.
Service를 지웠다 다시 만들면 ClusterIP는 **새로 배정된다.**
클러스터를 새로 구축하면 전부 달라진다. 환경마다 설정 파일을 따로 관리하게 된다.

### 이름으로 부르기

Service를 만들면 **그 이름이 곧 도메인**이 된다. IP를 알 필요가 없다.

```
Pod ──"clusterip1 어디야?"──▶ CoreDNS(10.96.0.10) ──▶ "10.100.x.x"
```

이름은 개발자가 정한 것이므로 **환경이 달라도 그대로다.**
개발 클러스터든 운영 클러스터든 `mysql`이라고 부르면 각자의 mysql에 닿는다.

전체 이름은 `<서비스명>.<네임스페이스>.svc.cluster.local` 인데,
같은 네임스페이스라면 **짧은 이름만으로 충분하다.**
Pod의 `/etc/resolv.conf`에 `search` 설정이 들어 있기 때문이다.

이 문서는 이 게시글 전체의 출발점이다. 뒤의 세 문서는 전부 **"그럼 이 DNS 응답을
다르게 만들면 어떻게 되는가"** 를 다룬다.

### 이 문서에서 확인할 것

- Service 이름이 실제로 무엇으로 풀리는가 (2절)
- 짧은 이름이 통하는 이유 — `resolv.conf`에 무엇이 있는가 (3절)
- 다른 네임스페이스의 Service는 어떻게 부르는가 (3절)
- 노드에서 직접 그 이름을 쓰면 되는가 (검증 절)

## 실습 시작 전 정리

```bash
clear                       # 화면 정리 후 시작

# default 네임스페이스의 실습 리소스를 전부 삭제 (시스템 네임스페이스는 건드리지 않는다)
kubectl delete pod,deploy,rs,statefulset,daemonset,job,cronjob \
  --all -n default --grace-period=1 --ignore-not-found

# Service는 kubernetes(클러스터 기본 서비스)만 남기고 삭제
kubectl delete svc -n default \
  --field-selector 'metadata.name!=kubernetes' --ignore-not-found

kubectl get all -n default  # service/kubernetes 만 남으면 정상
```

> **`-n default`를 반드시 붙인다.** `-A`(전 네임스페이스)로 실행하면 `kube-system`,
> `calico-system` 등 클러스터 구동에 필요한 리소스까지 지워져 **클러스터가 망가진다.**

## FQDN 규칙

```
<서비스명>.<네임스페이스>.svc.cluster.local
```

| 부르는 위치 | 쓸 수 있는 이름 |
|---|---|
| 같은 네임스페이스 | `clusterip1` |
| 다른 네임스페이스 | `clusterip1.default` |
| 어디서든 (완전한 이름) | `clusterip1.default.svc.cluster.local` |

## YAML

```bash
clear                                          # 화면 정리 후 시작
kubectl apply -f - <<'END'                     # clusterip1 — Service
apiVersion: v1
kind: Service
metadata:
  name: clusterip1                             # 이 이름이 그대로 도메인이 된다
spec:
  selector:
    svc: clusterip
  ports:
  - port: 80                                   # 도메인으로 부를 때의 포트
    targetPort: 8080
END
```

```bash
clear                                          # 화면 정리 후 시작
kubectl apply -f - <<'END'                     # pod1 — Pod
apiVersion: v1
kind: Pod
metadata:
  name: pod1
  labels:
    svc: clusterip                             # Service가 이 라벨로 찾는다
spec:
  containers:
  - name: container
    image: kubetm/app
END
```

```bash
clear                                          # 화면 정리 후 시작
kubectl apply -f - <<'END'                     # request-pod — Pod
apiVersion: v1
kind: Pod
metadata:
  name: request-pod                            # 클러스터 안에서 호출을 던져볼 Pod
spec:
  containers:
  - name: container
    image: kubetm/init
END
```

`request-pod`가 이 게시글 전체에서 **호출자 역할**을 한다.
DNS는 클러스터 안에서만 통하므로 master에서 직접 호출하면 안 된다.

## 실습 과정

### 1. DNS 질의

```bash
clear                                                                       # 화면 정리 후 시작
kubectl apply -f - <<'END'                                                  # Service와 Pod 2개 생성 (YAML은 위 절 참고)
# ... 위 YAML 전체 ...
END

kubectl wait --for=condition=Ready pod/pod1 pod/request-pod --timeout=180s  # 둘 다 뜰 때까지
kubectl get svc clusterip1                                                  # Service IP 확인
kubectl exec request-pod -- nslookup clusterip1                             # 짧은 이름으로 질의
```

```
clusterip1 IP: 10.105.21.216

Address:  10.96.0.10#53                        ← CoreDNS 가 답했다
Name:     clusterip1.default.svc.cluster.local
Address:  10.105.21.216                        ← Service IP 와 같다
```

**짧은 이름으로 물었는데 FQDN으로 답한다.**
Pod의 `/etc/resolv.conf`에 `search default.svc.cluster.local ...` 이 설정돼 있어
짧은 이름 뒤에 자동으로 붙여서 질의하기 때문이다.

### 2. 이름으로 호출

```bash
clear                                                                              # 화면 정리 후 시작
kubectl exec request-pod -- curl -s clusterip1/hostname                            # 짧은 이름으로 호출
kubectl exec request-pod -- curl -s clusterip1.default.svc.cluster.local/hostname  # FQDN 으로 호출
```

```
Hostname : pod1
```

Service IP를 몰라도 된다. **이름만 알면 된다.**
Pod이 재생성돼 IP가 바뀌어도, Service IP가 바뀌어도 이름은 그대로다.

> 애플리케이션 설정에 IP 대신 Service 이름을 쓰는 이유가 이것이다.
> `jdbc:mysql://mysql-svc:3306/...` 같은 식으로.

## 배운 것

- Service 이름이 곧 DNS 이름이다. CoreDNS(`10.96.0.10`)가 응답한다.
- FQDN은 `<서비스명>.<네임스페이스>.svc.cluster.local` 이다.
- 같은 네임스페이스에서는 **짧은 이름만으로** 충분하다.
- DNS는 **클러스터 안에서만** 통한다. 노드에서 직접 `curl clusterip1` 은 안 된다.
