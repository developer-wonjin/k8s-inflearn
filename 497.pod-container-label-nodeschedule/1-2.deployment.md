# 1-2) Deployment

원문 : https://cafe.naver.com/kubeops/497 (1. Container)

> 강의 영상의 ReplicationController는 현재 잘 쓰지 않아 Deployment로 대체된 부분이다.
> Deployment → ReplicaSet → Pod 3계층 구조를 확인하는 것이 목적.

## 실습 시작 전 정리

```bash
clear                       # 화면 정리 후 시작

# default 네임스페이스의 실습 리소스를 전부 삭제 (시스템 네임스페이스는 건드리지 않는다)
kubectl delete pod,deploy,rs,statefulset,daemonset,job,cronjob \
  --all -n default --grace-period=1 --ignore-not-found

# Service는 kubernetes(클러스터 기본 서비스)만 남기고 삭제
kubectl delete svc -n default \
  --field-selector 'metadata.name!=kubernetes' --ignore-not-found

kubectl get all -n default  # service/kubernetes 만 남으면 정상
```

> **`-n default`를 반드시 붙인다.** `-A`(전 네임스페이스)로 실행하면 `kube-system`,
> `calico-system` 등 클러스터 구동에 필요한 리소스까지 지워져 **클러스터가 망가진다.**
>
> `service/kubernetes`는 API 서버로 가는 기본 서비스라 `--field-selector`로 제외한다.
> 지워도 자동 재생성되지만 그 사이 통신이 끊긴다.

## YAML

```yaml
apiVersion: apps/v1            # Deployment는 apps 그룹의 v1
kind: Deployment               # 리소스 종류
metadata:
  name: deployment-1           # Deployment 이름
spec:
  replicas: 1                  # 유지할 Pod 개수 (ReplicaSet에 전달됨)
  selector:                    # 이 Deployment가 관리할 Pod을 고르는 조건
    matchLabels:               # 라벨이 정확히 일치하는 Pod만 관리
      app: deploy              # template.metadata.labels와 반드시 같아야 한다
  template:                    # 여기서부터가 "찍어낼 Pod의 설계도"
    metadata:
      labels:                  # template.metadata 에는 labels 만 둔다
        app: deploy            # 생성되는 Pod에 붙을 라벨 = selector와 일치
    spec:
      containers:              # Pod 안의 컨테이너 목록
      - name: container        # 컨테이너 이름
        image: kubetm/init     # 계속 떠 있기만 하는 실습용 이미지
```

> 원문 yaml에는 `template.metadata` 아래에 `name: pod-1`이 들어 있으나 이 문서에서는 뺐다.
> Pod 이름으로 쓰이지 않으면서(`generateName`이 이름을 만든다) `pod-template-hash`에는
> 포함되어, 넣고 빼는 것만으로 새 ReplicaSet이 생기고 롤아웃이 발생하는 필드다.

## 실습 과정

### 1. 생성과 3계층 구조 확인

```bash
clear                                                     # 화면 정리 후 시작
kubectl apply -f - <<'END'                                # 파일 없이 표준입력(heredoc)으로 생성 — YAML 각 줄 설명은 위 YAML 절 참고
apiVersion: apps/v1
kind: Deployment
metadata:
  name: deployment-1
spec:
  replicas: 1
  selector:
    matchLabels:
      app: deploy
  template:
    metadata:
      labels:
        app: deploy
    spec:
      containers:
      - name: container
        image: kubetm/init
END

kubectl rollout status deploy/deployment-1 --timeout=90s  # 롤아웃이 끝날 때까지 대기 (Pod 대상 wait와는 다름)
kubectl get deploy,rs,pod -o wide                         # Deploy·RS·Pod 3계층을 한 번에 조회
```

```
deployment.apps/deployment-1 created
deployment "deployment-1" successfully rolled out

NAME                           READY  UP-TO-DATE  AVAILABLE  IMAGES        SELECTOR
deployment.apps/deployment-1   1/1    1           1          kubetm/init   app=deploy

NAME                                     DESIRED  CURRENT  READY  IMAGES        SELECTOR
replicaset.apps/deployment-1-67cf8d676   1        1        1      kubetm/init   app=deploy,
                                                                               pod-template-hash=67cf8d676

NAME                               READY  STATUS   IP              NODE
pod/deployment-1-67cf8d676-d2wrq   1/1    Running  20.110.126.31   k8s-worker2
```

Deployment가 Pod을 **직접 만들지 않는다.** ReplicaSet을 만들고, ReplicaSet이 Pod을 만든다.

`pod-template-hash=67cf8d676`은 Pod 템플릿 전체를 해시한 값이며
**RS 이름 / Pod 이름 / RS selector** 세 곳에 모두 붙는다.
이 라벨 덕분에 여러 RS가 공존해도 서로의 Pod을 뺏어가지 않는다.

### 2. 소유 관계(ownerReferences)

```bash
clear  # 화면 정리 후 시작
# Pod의 소유자(ownerReferences)를 "이름 <- 종류/소유자" 형태로 출력 — 줄이 길어 주석을 위로 뺌
kubectl get pod -l app=deploy -o jsonpath='{range .items[*]}{.metadata.name}{" <- "}{.metadata.ownerReferences[0].kind}{"/"}{.metadata.ownerReferences[0].name}{"\n"}{end}'

# 같은 방식으로 ReplicaSet의 소유자도 확인 (pod → rs 로만 바꿈)
kubectl get rs  -l app=deploy -o jsonpath='{range .items[*]}{.metadata.name}{" <- "}{.metadata.ownerReferences[0].kind}{"/"}{.metadata.ownerReferences[0].name}{"\n"}{end}'
```

```
deployment-1-67cf8d676-d2wrq  <- ReplicaSet/deployment-1-67cf8d676
deployment-1-67cf8d676        <- Deployment/deployment-1
```

`Pod ─owner→ ReplicaSet ─owner→ Deployment` 로 사슬이 이어진다.
Deployment 하나만 지워도 아래가 전부 연쇄 삭제되는 이유다.

단독 Pod(1-1의 `pod-1`)은 `ownerReferences`가 `<none>`이라 지우면 그냥 사라진다.

### 3. 자가 복구 — Pod을 강제로 지워본다

```bash
clear                                                               # 화면 정리 후 시작
kubectl delete pod deployment-1-67cf8d676-d2wrq --grace-period=1    # RS가 관리하는 Pod을 강제로 삭제해 본다
kubectl wait --for=condition=Ready pod -l app=deploy --timeout=90s  # 새로 만들어진 Pod이 Ready 될 때까지 대기
kubectl get pod -l app=deploy                                       # 이름이 바뀐 새 Pod 확인
```

```
pod "deployment-1-67cf8d676-d2wrq" deleted
pod/deployment-1-67cf8d676-6h4br condition met

NAME                           READY   STATUS    RESTARTS   AGE
deployment-1-67cf8d676-6h4br   1/1     Running   0          30s
```

이름이 다른 새 Pod이 즉시 만들어졌다. ReplicaSet이 desired 수를 맞추기 때문.
**단독 Pod이었다면 그냥 사라진다.** Deployment를 쓰는 가장 큰 이유.

해시(`67cf8d676`)는 그대로고 랜덤 접미사만 바뀐다(`d2wrq` → `6h4br`).
템플릿이 안 바뀌었으므로 같은 RS 소속이다.

### 4. Pod 이름은 누가 짓는가

```bash
clear  # 화면 정리 후 시작
# 실제 Pod 이름과 generateName을 나란히 출력한다
kubectl get pod -l app=deploy -o custom-columns='NAME:.metadata.name,GENERATE_NAME:.metadata.generateName'
```

```
NAME                           GENERATE_NAME
deployment-1-67cf8d676-6h4br   deployment-1-67cf8d676-
```

Pod 이름 = **`generateName` + API 서버가 붙인 랜덤 5자**다.

`replicas`가 2 이상이면 같은 이름의 Pod을 여러 개 만들 수 없으므로
컨트롤러가 이름을 직접 지어야 한다. 사용자가 Pod 이름을 정할 수 없는 이유다.

`template.metadata`에 실제로 무엇이 들어가는지도 확인해 둔다.

```bash
clear                                                                    # 화면 정리 후 시작
kubectl get deploy deployment-1 -o jsonpath='{.spec.template.metadata}'  # 템플릿 메타데이터 원본
```

```
{"creationTimestamp":null,"labels":{"app":"deploy"}}
```

`labels`만 있으면 된다. 여기에 `name`을 넣어도 Pod 이름이 되지 않고,
해시만 바뀌어 불필요한 롤아웃을 유발한다.

### 정리

```bash
clear                               # 화면 정리 후 시작
kubectl delete deploy deployment-1  # Deployment만 지우면 RS와 Pod까지 연쇄 삭제된다
```

## 배운 것

- Deployment는 Pod을 직접 만들지 않는다. RS를 만들고 RS가 Pod을 만든다.
- `pod-template-hash`가 RS와 Pod을 묶는 열쇠다.
- Pod을 지워도 RS가 즉시 되살린다 (자가 복구).
- Pod 이름은 `generateName` + 랜덤 5자로 컨트롤러가 짓는다.
- `template.metadata`에는 `labels`(와 필요 시 `annotations`)만 둔다.
  `name`은 기능이 없으면서 해시만 바꿔 롤아웃을 유발한다.
