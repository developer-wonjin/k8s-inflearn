# 2) hostPath

원문 : https://cafe.naver.com/kubeops/499 (2. hostPath)

**워커 노드의 특정 경로**를 볼륨으로 쓴다.
같은 노드에 있는 여러 Pod이 이 경로를 공유한다.

> 원문 경고 그대로 **운영 환경에서는 권장하지 않는다.**
> Pod이 노드의 파일시스템에 직접 접근하므로, 경로만 잘 고르면 노드를 장악할 수 있다.
> 테스트나 노드 로그 수집처럼 목적이 분명할 때만 쓴다.

## 왜 필요한가

### 없으면 이렇게 된다

[1. emptyDir](1.emptydir.md)은 **Pod이 사라지면 같이 사라진다.**
컨테이너끼리 잠깐 주고받는 데는 충분하지만, 남겨야 하는 데이터에는 쓸 수 없다.

그리고 emptyDir은 **한 Pod 안에서만** 공유된다.
다른 Pod과 파일을 주고받아야 하면 방법이 없다.

### hostPath가 쓰는 것

hostPath는 볼륨의 실체를 Pod 밖으로 꺼낸다. **노드의 실제 디렉토리**를 그대로 붙인다.

| | emptyDir | hostPath |
|---|---|---|
| 실체 | Pod 전용 임시 공간 | **노드의 디렉토리** |
| Pod을 지우면 | 사라진다 | **남는다** |
| 공유 범위 | 한 Pod 안 | **같은 노드의 모든 Pod** |

Pod보다 오래 사는 저장 공간이 처음 생기는 지점이다.

다만 **노드에 묶인다.** Pod이 다른 노드로 옮겨가면 그 데이터는 보이지 않는다.
같은 경로라도 노드마다 내용이 다른, 완전히 별개의 디렉토리다.
그래서 이것도 최종 답이 아니고, [3. PV/PVC](3.pv-pvc.md)가 그 한계에서 출발한다.

> **운영에는 쓰지 않는다.** Pod이 노드 파일시스템에 직접 손대므로
> 경로만 잘 고르면 노드를 장악할 수 있다. 목적이 분명할 때만 쓴다.

### 이 문서에서 확인할 것

- 같은 노드의 두 Pod이 정말 같은 파일을 보는가 (1절)
- 노드가 다르면 어떻게 되는가 (2절)
- Pod을 지운 뒤 노드에는 무엇이 남는가 (3절)
- `type: DirectoryOrCreate`와 `Directory`의 차이는 언제 드러나는가 (YAML 절)

## 실습 시작 전 정리

```bash
clear                       # 화면 정리 후 시작

# default 네임스페이스의 실습 리소스를 전부 삭제 (시스템 네임스페이스는 건드리지 않는다)
kubectl delete pod,deploy,rs,statefulset,daemonset,job,cronjob \
  --all -n default --grace-period=1 --ignore-not-found

# Service는 kubernetes(클러스터 기본 서비스)만 남기고 삭제
kubectl delete svc -n default \
  --field-selector 'metadata.name!=kubernetes' --ignore-not-found

kubectl get all -n default  # service/kubernetes 만 남으면 정상
```

> **`-n default`를 반드시 붙인다.** `-A`(전 네임스페이스)로 실행하면 `kube-system`,
> `calico-system` 등 클러스터 구동에 필요한 리소스까지 지워져 **클러스터가 망가진다.**
>
> 노드에 만드는 `/node-v` 디렉토리는 파일시스템이라 이 정리로 지워지지 않는다.

## YAML

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: pod-volume-2
spec:
  nodeSelector:
    kubernetes.io/hostname: k8s-worker1        # 노드를 고정해야 같은 경로를 공유한다
  containers:
  - name: container
    image: kubetm/init
    volumeMounts:
    - name: host-path
      mountPath: /mount1                       # 컨테이너에서 보일 경로
  volumes:
  - name: host-path
    hostPath:
      path: /node-v                            # 노드(worker1)의 실제 경로
      type: DirectoryOrCreate                  # 없으면 만들어라
```

### `type` 옵션

| 값 | 뜻 |
|---|---|
| `DirectoryOrCreate` | 디렉토리가 없으면 만든다 |
| `Directory` | 디렉토리가 **반드시 있어야** 한다. 없으면 Pod이 못 뜬다 |
| `FileOrCreate` | 파일이 없으면 만든다 |
| `File` | 파일이 반드시 있어야 한다 |

## 실습 과정

### 1. 같은 노드의 두 Pod이 공유하는지

`pod-volume-2`와 `pod-volume-3`을 **둘 다 worker1에** 만든다 (YAML은 위와 동일, 이름만 다름).

```bash
clear                                                                                # 화면 정리 후 시작
kubectl apply -f - <<'END'                                                           # worker1에 Pod 2개 생성
# ... pod-volume-2, pod-volume-3 YAML ...
END

kubectl wait --for=condition=Ready pod/pod-volume-2 pod/pod-volume-3 --timeout=120s  # 둘 다 뜰 때까지
kubectl exec pod-volume-2 -- sh -c 'echo "file context" >> /mount1/file.txt'         # pod-volume-2 에서 파일 생성
kubectl exec pod-volume-3 -- cat /mount1/file.txt                                    # pod-volume-3 에서 읽어본다
```

```
file context
```

**다른 Pod인데 파일이 보인다.** `emptyDir`은 Pod 안에서만 공유됐지만
`hostPath`는 노드를 통해 Pod 간에도 공유된다.

### 검증: 다른 노드의 Pod은 어떻게 되는가

같은 `path: /node-v` 설정으로 **worker2에** `pod-volume-4`를 만든다.

```bash
clear                                                               # 화면 정리 후 시작
kubectl apply -f - <<'END'                                          # worker2에 pod-volume-4 생성 (path 는 동일)
# ... pod-volume-4 YAML (nodeSelector 만 k8s-worker2) ...
END

kubectl wait --for=condition=Ready pod/pod-volume-4 --timeout=120s  # 뜰 때까지 대기
kubectl exec pod-volume-2 -- ls -A /mount1                          # worker1의 Pod
kubectl exec pod-volume-4 -- ls -A /mount1                          # worker2의 Pod
```

```
worker1의 pod-volume-2 → file.txt
worker2의 pod-volume-4 → (비어 있음)
```

**노드마다 완전히 별개다.** yaml에 적은 경로가 같아도 실제 디렉토리는 각 노드의 것이다.

여기서 hostPath의 결정적인 한계가 나온다.

> Pod은 재생성될 때 **다른 노드로 갈 수 있다.** 그러면 데이터가 통째로 사라진 것처럼 보인다.
> `nodeSelector`로 노드를 묶어두면 되지만, 그건 곧 **스케줄러의 자유를 포기**하는 것이다.
> 그 노드가 죽으면 Pod도 뜨지 못한다.
>
> 이 문제를 제대로 풀려면 노드에 묶이지 않는 저장소가 필요하다 → [3.pv-pvc.md](3.pv-pvc.md)

### 정리

```bash
clear  # 화면 정리 후 시작
kubectl delete pod \
  pod-volume-2 \
  pod-volume-3 \
  pod-volume-4 \
  --grace-period=1 --ignore-not-found
```

> Pod을 지워도 **노드의 `/node-v` 디렉토리와 파일은 남는다.**
> hostPath는 노드의 디렉토리를 빌려 쓸 뿐이라 쿠버네티스가 청소해주지 않는다.
> 다음 문서(PV/PVC)에서 이 디렉토리를 그대로 다시 쓴다.

## 배운 것

- `hostPath`는 **노드의 디렉토리**를 Pod에 붙인다.
- 같은 노드의 Pod끼리는 공유되지만 **노드가 다르면 완전히 별개**다.
- `type: DirectoryOrCreate`는 경로가 없으면 만들어준다. `Directory`는 없으면 Pod이 실패한다.
- Pod을 지워도 노드의 디렉토리는 남는다.
- 노드에 묶이는 구조라 운영에는 부적합하다. 보안 위험도 있다.
