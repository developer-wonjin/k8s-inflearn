# 1) emptyDir

원문 : https://cafe.naver.com/kubeops/499 (1. emptyDir)

**한 Pod 안의 컨테이너끼리 파일을 주고받기 위한** 볼륨.
Pod이 삭제되면 내용도 함께 사라지므로 없어져도 되는 데이터만 담는다.

> 497 부록에서 확인했듯 한 Pod 안의 컨테이너는 `mnt` 네임스페이스가 서로 다르다.
> 그래서 파일이 안 보인다. emptyDir은 그 사이에 **공용 디렉토리를 하나 끼워 넣는 장치**다.

## 왜 필요한가

### 없으면 이렇게 된다

같은 Pod 안에 컨테이너를 두 개 넣었다고 해서 **파일이 서로 보이지는 않는다.**
[497 부록](../부록%29%20네트워크/네트워크-네임스페이스-공유.md)에서 확인했듯
컨테이너들은 네트워크는 공유하지만 **`mnt` 네임스페이스는 각자 따로** 쓴다.

그래서 웹 서버 컨테이너가 만든 로그 파일을 로그 수집 컨테이너가 읽으려 해도
**경로가 없다고 나온다.** `localhost`로 통신은 되는데 파일은 못 주고받는 상태다.

### emptyDir이 끼워 넣는 것

emptyDir은 그 사이에 **공용 디렉토리를 하나 만들어 양쪽에 붙여준다.**

```
컨테이너 A ──/mount1──┐
                      ├──▶ 같은 emptyDir 볼륨
컨테이너 B ──/mount2──┘
```

**붙이는 경로는 달라도 된다.** 컨테이너마다 자기 사정에 맞는 경로를 쓰고,
실제로는 같은 곳을 보게 된다.

이름이 `emptyDir`인 이유는 **Pod이 뜰 때 빈 디렉토리로 시작**하기 때문이다.
그리고 Pod이 사라지면 같이 사라진다. **수명이 Pod에 묶여 있다**는 것이
이 볼륨의 성격이자 한계이며, 다음 두 문서가 그 한계에서 출발한다.

### 이 문서에서 확인할 것

- 한 볼륨을 컨테이너마다 **다른 경로**로 붙일 수 있는가 (1절)
- 한쪽에서 만든 파일이 정말 다른 쪽에서 보이는가 (2절)
- 그 파일은 Pod을 지워도 남는가 (3절)

## 실습 시작 전 정리

```bash
clear                       # 화면 정리 후 시작

# default 네임스페이스의 실습 리소스를 전부 삭제 (시스템 네임스페이스는 건드리지 않는다)
kubectl delete pod,deploy,rs,statefulset,daemonset,job,cronjob \
  --all -n default --grace-period=1 --ignore-not-found

# Service는 kubernetes(클러스터 기본 서비스)만 남기고 삭제
kubectl delete svc -n default \
  --field-selector 'metadata.name!=kubernetes' --ignore-not-found

kubectl get all -n default  # service/kubernetes 만 남으면 정상
```

> **`-n default`를 반드시 붙인다.** `-A`(전 네임스페이스)로 실행하면 `kube-system`,
> `calico-system` 등 클러스터 구동에 필요한 리소스까지 지워져 **클러스터가 망가진다.**

## YAML

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: pod-volume-1
spec:
  containers:
  - name: container1
    image: kubetm/init
    volumeMounts:                              # 이 컨테이너에 볼륨을 붙인다
    - name: empty-dir                          # 아래 volumes 에서 정의한 이름
      mountPath: /mount1                       # 이 컨테이너에서 보일 경로
  - name: container2
    image: kubetm/init
    volumeMounts:
    - name: empty-dir                          # 같은 볼륨을
      mountPath: /mount2                       # 다른 경로로 붙여도 된다
  volumes:                                     # Pod이 가진 볼륨 목록
  - name: empty-dir                            # 볼륨 이름 (컨테이너가 참조)
    emptyDir: {}                               # 빈 디렉토리로 시작. 옵션 없으면 {} 로 둔다
```

## 실습 과정

### 1. 생성과 마운트 확인

```bash
clear                                                               # 화면 정리 후 시작
kubectl apply -f - <<'END'                                          # Pod 생성 (YAML은 위 절 참고)
# ... 위 YAML 전체 ...
END

kubectl wait --for=condition=Ready pod/pod-volume-1 --timeout=120s  # 컨테이너 2개가 모두 Ready 될 때까지
kubectl exec pod-volume-1 -c container1 -- mount | grep mount1      # 실제로 마운트됐는지
```

```
/dev/sda4 on /mount1 type xfs (rw,relatime,seclabel,...)
```

노드의 디스크(`/dev/sda4`) 일부가 `/mount1`로 붙었다.
`emptyDir`은 이름과 달리 메모리가 아니라 **노드 디스크**를 쓴다
(`emptyDir: {medium: Memory}`로 바꾸면 tmpfs가 된다).

### 2. 컨테이너 간 공유 확인

```bash
clear                                                                                       # 화면 정리 후 시작
kubectl exec pod-volume-1 -c container1 -- sh -c 'echo "file context" >> /mount1/file.txt'  # container1이 파일 생성
kubectl exec pod-volume-1 -c container2 -- ls -l /mount2                                    # container2의 다른 경로에서 조회
kubectl exec pod-volume-1 -c container2 -- cat /mount2/file.txt                             # 내용까지 읽어본다
```

```
total 4
-rw-r--r--. 1 root root 13 Sep  5 12:47 file.txt
file context
```

`container1`이 `/mount1`에 만든 파일이 `container2`의 `/mount2`에 보인다.
**경로 이름이 달라도 같은 디렉토리**다.

### 검증: Pod을 지우면 정말 사라지는가

```bash
clear                                                               # 화면 정리 후 시작
kubectl delete pod pod-volume-1 --grace-period=1                    # Pod 삭제
kubectl apply -f - <<'END'                                          # 같은 정의로 재생성
# ... 위 YAML 전체 ...
END
kubectl wait --for=condition=Ready pod/pod-volume-1 --timeout=120s  # 다시 뜰 때까지 대기
kubectl exec pod-volume-1 -c container1 -- ls -A /mount1            # 파일이 남아 있는가
```

```
(출력 없음 — 비어 있다)
```

**완전히 사라졌다.** `emptyDir`의 수명은 Pod과 같다.
Pod을 지웠다 만들면 이름이 같아도 새 볼륨이 붙는다.

> 컨테이너가 재시작되는 것과는 다르다. Pod이 살아 있는 채로 컨테이너만 죽었다 살아나면
> 볼륨은 유지된다. 사라지는 기준은 **Pod의 삭제**다.

### 정리

```bash
clear                                                                # 화면 정리 후 시작
kubectl delete pod pod-volume-1 --grace-period=1 --ignore-not-found  # 이 문서에서 만든 Pod 삭제
```

## 배운 것

- `emptyDir`은 **한 Pod 안**의 컨테이너끼리 파일을 공유하는 용도다.
- 같은 볼륨을 컨테이너마다 **다른 경로로** 붙일 수 있다.
- 실제 저장소는 노드 디스크다. `medium: Memory`로 tmpfs를 쓸 수도 있다.
- 수명이 Pod과 같다. Pod을 지우면 데이터가 사라진다.
- 다른 Pod과는 공유되지 않는다. 그것이 필요하면 hostPath나 PV를 쓴다.
