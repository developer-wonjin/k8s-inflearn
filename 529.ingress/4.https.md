# 4) HTTPS — Ingress에 인증서 붙이기

원문 : https://cafe.naver.com/kubeops/529 (4. Https)

- 선행 조건 : [1번](1.nginx-controller.md)의 Nginx Controller

애플리케이션은 그대로 http(8080)로 두고, **nginx가 TLS를 처리**하게 한다.
인증서를 앱마다 넣을 필요가 없어진다 (TLS termination).

```
[사용자] ──https──▶ nginx (여기서 복호화) ──http──▶ Service ──▶ Pod
                    인증서는 여기만 있으면 된다
```

## 인증서와 Secret 만들기

```bash
clear  # 화면 정리 후 시작
# 자체 서명 인증서 생성 (CN 이 접속할 도메인과 같아야 한다)
openssl req -x509 -nodes -days 365 -newkey rsa:2048 \
  -keyout tls.key -out tls.crt \
  -subj "/CN=www.https.com/O=www.https.com"

# 인증서를 Secret 으로 등록한다
kubectl create secret tls secret-https --key tls.key --cert tls.crt
```

```
secret/secret-https created
```

`kubectl create secret tls` 는 **전용 명령**이다.
`type: kubernetes.io/tls` 인 Secret을 만들고 `tls.crt` / `tls.key` 키에 넣어준다.
게시글 500에서 본 `generic` Secret과 형식이 다르다.

## YAML

```yaml
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: https
spec:
  ingressClassName: nginx
  tls:                                         # 이 블록이 HTTPS 를 켠다
  - hosts:
    - www.https.com                            # 이 호스트로 올 때
    secretName: secret-https                   # 이 인증서를 쓴다
  rules:
  - host: www.https.com
    http:                                      # 뒷단은 여전히 http 다
      paths:
      - path: /
        pathType: Prefix
        backend:
          service:
            name: svc-https
            port:
              number: 8080                     # Pod 은 평범한 http 8080
```

## 실습 과정

```bash
clear                                                            # 화면 정리 후 시작
kubectl apply -f - <<'END'                                       # Pod, Service, Ingress 생성
# ... pod-https, svc-https, https Ingress YAML ...
END

kubectl wait --for=condition=Ready pod/pod-https --timeout=240s  # 대기
grep -q 'www.https.com' /etc/hosts || echo '192.168.56.30 www.https.com' >> /etc/hosts

# https 는 30798 포트다 (http 는 30431)
curl -k https://www.https.com:30798/hostname
```

```
Hostname : pod-https
```

**`-k` 가 필요하다.** 자체 서명 인증서라 신뢰할 수 있는 CA가 서명하지 않았기 때문이다.
브라우저에서는 경고 화면이 뜨고 "계속 진행"을 눌러야 한다.

### 어떤 인증서가 쓰였는지 확인

```bash
clear  # 화면 정리 후 시작
echo | openssl s_client -connect www.https.com:30798 -servername www.https.com 2>/dev/null \
  | openssl x509 -noout -subject
```

```
subject=CN = www.https.com, O = www.https.com
```

**방금 만든 인증서가 실제로 쓰이고 있다.** Secret에 넣은 것을 nginx가 읽어 적용한 것이다.

### http로 접속하면

```bash
clear                                                                           # 화면 정리 후 시작
curl -o /dev/null -w 'HTTP %{http_code}\n' http://www.https.com:30431/hostname  # http 포트로
```

```
HTTP 308
```

**308 Permanent Redirect.** nginx가 자동으로 https로 돌려보낸다.
`tls` 를 설정하면 기본으로 켜지는 동작이다(`force-ssl-redirect`).

끄고 싶으면 annotation을 준다.

```yaml
metadata:
  annotations:
    nginx.ingress.kubernetes.io/ssl-redirect: "false"
```

### 정리

```bash
clear                                                             # 화면 정리 후 시작
kubectl delete ingress https --ignore-not-found                   # Ingress 삭제
kubectl delete pod pod-https --grace-period=1 --ignore-not-found  # Pod 삭제
kubectl delete svc svc-https --ignore-not-found                   # Service 삭제
kubectl delete secret secret-https --ignore-not-found             # 인증서 Secret 삭제
rm -f tls.key tls.crt                                             # 로컬 인증서 파일 삭제
sed -i '/www.https.com/d' /etc/hosts                              # hosts 정리
```

## 배운 것

- Ingress의 `tls` 블록에 **Secret 이름만** 적으면 HTTPS가 켜진다.
- 인증서는 `kubectl create secret tls` 로 만든다 (`type: kubernetes.io/tls`).
- **앱은 http 그대로 둔다.** nginx가 복호화해서 넘겨준다 (TLS termination).
- 인증서의 `CN` 이 접속 도메인과 같아야 한다.
- `tls` 를 설정하면 http 요청은 **자동으로 https로 리다이렉트**된다 (308).
- 자체 서명 인증서는 `curl -k` 나 브라우저 경고 통과가 필요하다.
