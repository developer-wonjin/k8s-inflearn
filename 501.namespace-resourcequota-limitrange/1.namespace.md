# 1) Namespace

원문 : https://cafe.naver.com/kubeops/501 (1. Namespace)

리소스를 **논리적으로 갈라놓는 그룹**. 팀별·환경별로 나눌 때 쓴다.
중요한 건 **무엇이 갈리고 무엇이 안 갈리는지**다.

## 왜 필요한가

### 없으면 이렇게 된다

클러스터 하나를 여러 팀이 같이 쓰면 **이름부터 부딪힌다.**
A팀도 `nginx`라는 Deployment를 만들고 싶고 B팀도 그렇다. 하나만 만들 수 있다.

권한도 문제다. 전부 한 곳에 있으면 **A팀에게만 권한을 주는 방법이 없다.**
`kubectl get pods`를 허용하면 다른 팀 Pod까지 전부 보인다.

### Namespace가 가르는 것

Namespace는 리소스를 **논리적인 그룹으로 나눈다.** 그룹이 다르면 같은 이름을 써도 된다.

이 문서에서 가장 중요한 것은 **무엇이 갈리고 무엇이 안 갈리는지**다.
이름이 "namespace(이름 공간)"인 만큼, 갈리는 것은 생각보다 좁다.

| 갈린다 | 갈리지 않는다 |
|---|---|
| 오브젝트 **이름** | **네트워크** — Pod IP·Service IP가 그대로 통한다 |
| Service의 selector 범위 | **NodePort** — 클러스터 전체에서 유일해야 한다 |
| RBAC 권한 | **노드 자원** — 같은 노드를 그대로 나눠 쓴다 |

> **격리 장벽이 아니다.** 다른 네임스페이스의 Pod에 IP로 접속하면 그냥 된다.
> 네트워크를 막으려면 NetworkPolicy가 따로 필요하다.
> 이 오해를 실제로 깨보는 것이 이 문서의 핵심이다.

### 이 문서에서 확인할 것

- 다른 네임스페이스에 **같은 이름**의 Pod을 만들 수 있는가 (2절)
- 네임스페이스가 다른 Pod끼리 **통신이 되는가** (3절)
- Service의 selector가 다른 네임스페이스의 Pod을 잡는가 (3절)
- 네임스페이스를 지우면 안의 리소스는 어떻게 되는가 (4절)

## 실습 시작 전 정리

```bash
clear                       # 화면 정리 후 시작

# default 네임스페이스의 실습 리소스를 전부 삭제 (시스템 네임스페이스는 건드리지 않는다)
kubectl delete pod,deploy,rs,statefulset,daemonset,job,cronjob \
  --all -n default --grace-period=1 --ignore-not-found

# Service는 kubernetes(클러스터 기본 서비스)만 남기고 삭제
kubectl delete svc -n default \
  --field-selector 'metadata.name!=kubernetes' --ignore-not-found

# 이 문서가 만드는 네임스페이스를 지운다 (안에 든 리소스도 함께 사라진다)
kubectl delete namespace \
  nm-1 \
  nm-2 \
  --ignore-not-found

kubectl get all -n default  # service/kubernetes 만 남으면 정상
```

> **`-n default`를 반드시 붙인다.** `-A`(전 네임스페이스)로 실행하면 `kube-system`,
> `calico-system` 등 클러스터 구동에 필요한 리소스까지 지워져 **클러스터가 망가진다.**
>
> `nm-*` 밖의 네임스페이스는 건드리지 않는다.

## YAML

```yaml
apiVersion: v1
kind: Namespace
metadata:
  name: nm-1                                   # 네임스페이스는 이름만 있으면 된다
---
apiVersion: v1
kind: Pod
metadata:
  name: pod-1
  namespace: nm-1                              # 이 줄로 소속이 정해진다
  labels:
    app: pod
spec:
  containers:
  - name: container
    image: kubetm/app
    ports:
    - containerPort: 8080
---
apiVersion: v1
kind: Service
metadata:
  name: svc-1
  namespace: nm-1
spec:
  selector:
    app: pod                                   # 같은 네임스페이스의 Pod만 찾는다
  ports:
  - port: 9000
    targetPort: 8080
```

`nm-2`에도 **똑같은 이름**(`pod-1`, `svc-1`)으로 하나 더 만든다.

## 실습 과정

### 1. 이름 중복이 되는가

```bash
clear                                                                # 화면 정리 후 시작
kubectl apply -f - <<'END'                                           # nm-1, nm-2 에 같은 이름으로 Pod/Service 생성
# ... nm-1, nm-2 YAML 전체 ...
END

kubectl wait --for=condition=Ready pod/pod-1 -n nm-1 --timeout=120s  # nm-1 Pod 대기
kubectl wait --for=condition=Ready pod/pod-1 -n nm-2 --timeout=120s  # nm-2 Pod 대기
kubectl get pod,svc -n nm-1                                          # nm-1 쪽
kubectl get pod,svc -n nm-2                                          # nm-2 쪽
```

```
nm-1: pod/pod-1  1/1  Running       service/svc-1  ClusterIP  10.100.99.86
nm-2: pod/pod-1  1/1  Running       service/svc-1  ClusterIP  10.106.120.68
```

**같은 이름이 공존한다.** 네임스페이스가 다르면 이름이 겹쳐도 된다.
Service IP는 각각 따로 받았다.

### 2. Service selector는 네임스페이스를 넘는가

```bash
clear  # 화면 정리 후 시작
# 각 Service가 실제로 어느 네임스페이스의 Pod을 잡았는지 본다
kubectl get endpoints svc-1 -n nm-1 -o jsonpath='{range .subsets[*].addresses[*]}{.targetRef.namespace}{"/"}{.targetRef.name}{"\n"}{end}'
kubectl get endpoints svc-1 -n nm-2 -o jsonpath='{range .subsets[*].addresses[*]}{.targetRef.namespace}{"/"}{.targetRef.name}{"\n"}{end}'
```

```
nm-1/svc-1 → nm-1/pod-1
nm-2/svc-1 → nm-2/pod-1
```

두 Pod 모두 `app: pod` 라벨을 갖고 있는데도 **각자 자기 네임스페이스의 Pod만** 잡았다.
`selector`는 네임스페이스를 넘지 않는다.

### 3. 그런데 네트워크 통신은 넘어간다

`nm-2`의 Pod에서 `nm-1`의 자원을 세 가지 방법으로 불러본다.

```bash
clear                                                                # 화면 정리 후 시작
P1=$(kubectl get pod pod-1 -n nm-1 -o jsonpath='{.status.podIP}')    # nm-1 Pod IP
S1=$(kubectl get svc svc-1 -n nm-1 -o jsonpath='{.spec.clusterIP}')  # nm-1 Service IP

kubectl exec pod-1 -n nm-2 -- curl -s $P1:8080/hostname              # ① Pod IP로 직접
kubectl exec pod-1 -n nm-2 -- curl -s $S1:9000/hostname              # ② Service IP로
kubectl exec pod-1 -n nm-2 -- curl -s svc-1.nm-1:9000/hostname       # ③ DNS 이름으로
```

```
① Pod IP 직접      → Hostname : pod-1
② Service IP       → Hostname : pod-1
③ svc-1.nm-1:9000  → Hostname : pod-1
```

**셋 다 된다.** 네임스페이스는 이름을 가르는 장치일 뿐 **네트워크 방화벽이 아니다.**

③번이 실무에서 쓰는 방식이다. DNS 이름은 `<서비스명>.<네임스페이스>` 형태이고,
같은 네임스페이스 안에서는 `<서비스명>`만 써도 된다.

> 네임스페이스 간 통신을 정말 막으려면 **NetworkPolicy**를 따로 걸어야 한다.

### 4. 네임스페이스로 갈리지 않는 것 — NodePort

```bash
clear                       # 화면 정리 후 시작
kubectl apply -f - <<'END'  # nm-1 에 nodePort 30001 서비스
# ... svc-2 (nm-1, nodePort 30001) ...
END
kubectl apply -f - <<'END'  # nm-2 에 같은 30001 로 시도
# ... svc-2 (nm-2, nodePort 30001) ...
END
```

```
service/svc-2 created                          ← nm-1 은 성공
The Service "svc-2" is invalid: spec.ports[0].nodePort:
  Invalid value: 30001: provided port is already allocated    ← nm-2 는 실패
```

**노드 포트는 클러스터 전체에서 하나뿐이다.** 노드의 실제 포트를 여는 것이라
네임스페이스로 나눌 수 없다.

### 5. 네임스페이스로 갈리지 않는 것 — hostPath

```bash
clear                                                                              # 화면 정리 후 시작
# nm-1, nm-2 각각에 worker1의 /node-v 를 마운트하는 Pod을 만든다
kubectl apply -f - <<'END'
# ... pod-2 (nm-1), pod-2 (nm-2) — 둘 다 hostPath /node-v ...
END

kubectl exec pod-2 -n nm-1 -- sh -c 'echo "hello from nm-1" >> /mount1/hello.txt'  # nm-1 에서 파일 생성
kubectl exec pod-2 -n nm-2 -- cat /mount1/hello.txt                                # nm-2 에서 읽어본다
```

```
hello from nm-1
```

**노드의 디렉토리도 네임스페이스를 넘어 공유된다.** 물리적인 자원이기 때문이다.

### 정리

```bash
clear                        # 화면 정리 후 시작
kubectl delete ns nm-1 nm-2  # 네임스페이스를 지우면 안의 리소스가 전부 함께 삭제된다
```

## 배운 것

| 갈리는 것 | 갈리지 않는 것 |
|---|---|
| 오브젝트 **이름** (중복 허용) | **네트워크** — Pod IP·Service IP·DNS 전부 통한다 |
| Service의 **selector** 범위 | **NodePort** — 클러스터 전체에서 유일해야 한다 |
| RBAC 권한 (게시글 525) | **노드 자원** — hostPath 등은 그대로 공유된다 |

- 네임스페이스는 **이름 충돌을 막고 권한을 나누는** 장치다. 격리 장벽이 아니다.
- 다른 네임스페이스의 Service는 `<서비스명>.<네임스페이스>` 로 부른다.
- 네임스페이스를 지우면 **안에 있던 모든 오브젝트가 함께 사라진다.**
