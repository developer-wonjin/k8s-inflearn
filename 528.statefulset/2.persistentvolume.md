# 2) PersistentVolumeClaim — Pod마다 자기 볼륨

원문 : https://cafe.naver.com/kubeops/528 (2. PersistentVolumeClaim)

이름과 순서보다 **더 중요한 차이**가 볼륨이다.

| | ReplicaSet | StatefulSet |
|---|---|---|
| PVC | 사람이 **하나** 만들어 둔다 | `volumeClaimTemplates` 로 **Pod마다 자동 생성** |
| 볼륨 공유 | 모든 Pod이 **같은 볼륨** | **각자 다른 볼륨** |
| Pod 재생성 시 | (공유라 무관) | **원래 쓰던 볼륨에 다시 붙는다** |

## 왜 필요한가

### 없으면 이렇게 된다

[1번](1.pod-naming-order.md)에서 이름은 고정됐다. 하지만 **데이터가 따라오지 않으면**
이름만 같은 빈 껍데기다.

ReplicaSet에 PVC를 붙이면 어떻게 되는지 생각해 보자.
PVC는 사람이 **하나** 만들고, 모든 Pod이 **그것을 공유**한다.

DB 복제 구성에서 이것은 재앙이다. primary와 replica가 **같은 디스크에 동시에 쓴다.**
각자 다른 데이터를 가져야 하는데 그럴 방법이 없다.

PVC를 Pod 수만큼 손으로 만들어도 문제는 남는다.
**어느 Pod이 어느 PVC를 쓸지 고정할 수 없다.** 재생성되면 뒤바뀔 수 있다.

### volumeClaimTemplates가 묶는 것

StatefulSet은 PVC를 **찍어내는 틀**을 갖는다. Pod마다 자기 PVC가 자동으로 생긴다.

```
stateful-pvc-0  ──▶  pvc-stateful-pvc-0   (이 Pod 전용)
stateful-pvc-1  ──▶  pvc-stateful-pvc-1   (이 Pod 전용)
```

이름에 순번이 들어가므로 **Pod 번호와 PVC가 영구히 짝지어진다.**
`-0`이 죽었다 살아나도 **원래 쓰던 볼륨에 다시 붙는다.** 데이터가 그대로 돌아온다.

| | ReplicaSet | StatefulSet |
|---|---|---|
| PVC | 사람이 **하나** 만든다 | **Pod마다 자동 생성** |
| 볼륨 | 모든 Pod이 **공유** | **각자 다른 볼륨** |
| 재생성 시 | (공유라 무관) | **원래 볼륨에 다시 붙는다** |

> **StatefulSet을 지워도 PVC는 남는다.** 실수로 지웠을 때 데이터를 잃지 않기 위한
> 의도된 동작이다. 정리는 직접 해야 한다.

### 이 문서에서 확인할 것

- `volumeClaimTemplates`로 PVC가 몇 개 생기는가, 이름은 (2절)
- Pod을 지우면 **같은 데이터**로 돌아오는가 (3절)
- `replicas`를 늘리면 PVC도 따라 늘어나는가 (4절)
- StatefulSet을 지우면 PVC는 어떻게 되는가 (정리 절)

## 실습 시작 전 정리

```bash
clear                       # 화면 정리 후 시작

# default 네임스페이스의 실습 리소스를 전부 삭제 (시스템 네임스페이스는 건드리지 않는다)
kubectl delete pod,deploy,rs,statefulset,daemonset,job,cronjob \
  --all -n default --grace-period=1 --ignore-not-found

# Service는 kubernetes(클러스터 기본 서비스)만 남기고 삭제
kubectl delete svc -n default \
  --field-selector 'metadata.name!=kubernetes' --ignore-not-found

# 이 문서는 PVC도 만든다 — 함께 비운다 (PV는 클러스터 범위라 문서 안에서 따로 다룬다)
kubectl delete pvc --all -n default --ignore-not-found

kubectl get all -n default  # service/kubernetes 만 남으면 정상
```

> **`-n default`를 반드시 붙인다.** `-A`(전 네임스페이스)로 실행하면 `kube-system`,
> `calico-system` 등 클러스터 구동에 필요한 리소스까지 지워져 **클러스터가 망가진다.**
>
> PV와 StorageClass는 클러스터 범위라 문서 안에서 따로 다룬다.

## 이 환경에서의 대체 구성

원문은 `storageClassName: "fast"` 를 쓴다. 게시글 518에서 Longhorn을 설치해 만드는 것이다.

> **이 실습에서는 Longhorn을 설치하지 않았다.**
> Longhorn은 모든 노드에 iscsi 패키지가 필요한데 워커 노드에 접근할 수 없었다.
>
> 대신 **`fast` StorageClass와 PV를 수동으로 만들어** 같은 동작을 확인했다.
> 동적 프로비저닝(PV 자동 생성)만 빠지고, StatefulSet의 볼륨 동작은 동일하게 관찰된다.

```bash
clear              # 화면 정리 후 시작
# 프로비저너 없는 StorageClass (이름만 맞추면 PVC 가 PV 를 찾아간다)
kubectl apply -f - <<'END'
apiVersion: storage.k8s.io/v1
kind: StorageClass
metadata:
  name: fast
provisioner: kubernetes.io/no-provisioner
volumeBindingMode: WaitForFirstConsumer
END

# PVC 가 붙을 PV 를 4개 미리 만든다
for i in 1 2 3 4; do
kubectl apply -f - <<EOF
apiVersion: v1
kind: PersistentVolume
metadata:
  name: manual-pv-$i
spec:
  capacity:
    storage: 1G
  accessModes:
  - ReadWriteOnce
  storageClassName: fast
  persistentVolumeReclaimPolicy: Delete
  hostPath:
    path: /tmp/sts-vol-$i
    type: DirectoryOrCreate
EOF
done

kubectl get sc,pv  # Available 상태로 대기 중인지 확인
```

## 2-2) ReplicaSet — 하나의 볼륨을 셋이 공유

```yaml
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: replica-pvc1                           # 사람이 직접 하나 만든다
spec:
  accessModes:
  - ReadWriteOnce
  resources:
    requests:
      storage: 1G
  storageClassName: "fast"
---
apiVersion: apps/v1
kind: ReplicaSet
metadata:
  name: replica-pvc
spec:
  replicas: 3
  selector:
    matchLabels:
      type: web2
  template:
    metadata:
      labels:
        type: web2
    spec:
      nodeSelector:
        kubernetes.io/hostname: k8s-worker1    # RWO 라 한 노드에 모아야 한다
      containers:
      - name: container
        image: kubetm/init
        volumeMounts:
        - name: vol
          mountPath: /applog
      volumes:
      - name: vol
        persistentVolumeClaim:
          claimName: replica-pvc1              # 세 Pod 이 모두 이 PVC 하나를 본다
      terminationGracePeriodSeconds: 10
```

```bash
clear                                                               # 화면 정리 후 시작
kubectl apply -f - <<'END'                                          # PVC와 ReplicaSet 생성
# ... 위 YAML ...
END

kubectl wait --for=condition=Ready pod -l type=web2 --timeout=180s  # 3개가 뜰 때까지
kubectl get pvc replica-pvc1                                        # PVC 는 하나뿐이다

# 한 Pod 에서 파일을 만들고 세 Pod 모두에서 확인한다
P=$(kubectl get pod -l type=web2 -o jsonpath='{.items[0].metadata.name}')
kubectl exec "$P" -- touch /applog/server.log
for p in $(kubectl get pod -l type=web2 -o jsonpath='{range .items[*]}{.metadata.name} {end}'); do
  echo -n "  $p → "; kubectl exec "$p" -- ls /applog
done
```

```
NAME           STATUS   VOLUME        CAPACITY   STORAGECLASS
replica-pvc1   Bound    manual-pv-1   1G         fast

  replica-pvc-crktr → server.log
  replica-pvc-p2mhw → server.log
  replica-pvc-qm6kl → server.log
```

**세 Pod이 같은 파일을 본다.** PVC가 하나이므로 당연하다.

## 2-3) StatefulSet — Pod마다 자기 볼륨

```yaml
apiVersion: apps/v1
kind: StatefulSet
metadata:
  name: stateful-pvc
spec:
  replicas: 2
  selector:
    matchLabels:
      type: db2
  serviceName: "stateful-headless"             # Headless Service 이름 (3번 문서)
  template:
    metadata:
      labels:
        type: db2
    spec:
      containers:
      - name: container
        image: kubetm/app
        volumeMounts:
        - name: volume                         # 아래 템플릿의 이름과 맞춘다
          mountPath: /applog
      terminationGracePeriodSeconds: 10
  volumeClaimTemplates:                        # PVC 를 "찍어내는 틀"
  - metadata:
      name: volume
    spec:
      accessModes:
      - ReadWriteOnce
      resources:
        requests:
          storage: 1G
      storageClassName: "fast"
```

```bash
clear                                                              # 화면 정리 후 시작
kubectl apply -f - <<'END'                                         # Headless Service 와 StatefulSet 생성
# ... stateful-headless, stateful-pvc YAML ...
END

kubectl wait --for=condition=Ready pod -l type=db2 --timeout=240s  # 뜰 때까지
kubectl get pvc                                                    # PVC 가 몇 개인가
```

```
NAME                    STATUS   VOLUME        CAPACITY   STORAGECLASS
replica-pvc1            Bound    manual-pv-1   1G         fast
volume-stateful-pvc-0   Bound    manual-pv-3   1G         fast     ← 자동 생성
volume-stateful-pvc-1   Bound    manual-pv-2   1G         fast     ← 자동 생성
```

**PVC가 Pod마다 하나씩 자동으로 만들어졌다.** 이름 규칙은 이렇다.

```
<volumeClaimTemplates의 name>-<StatefulSet이름>-<순번>
        volume            -  stateful-pvc  -  0
```

```bash
clear                                                    # 화면 정리 후 시작
kubectl exec stateful-pvc-0 -- touch /applog/server.log  # 0번에서만 파일 생성
kubectl exec stateful-pvc-0 -- ls -A /applog             # 0번에서 확인
kubectl exec stateful-pvc-1 -- ls -A /applog             # 1번에서 확인
```

```
stateful-pvc-0 → server.log
stateful-pvc-1 → (비어있음)
```

**공유되지 않는다.** 각자 자기 볼륨을 쓴다.

## 검증: Pod을 지우면 볼륨은 어떻게 되는가

StatefulSet의 존재 이유가 여기 있다.

```bash
clear                                                                                            # 화면 정리 후 시작
kubectl get pod stateful-pvc-0 -o jsonpath='{.spec.volumes[0].persistentVolumeClaim.claimName}'  # 삭제 전 PVC
kubectl delete pod stateful-pvc-0 --grace-period=1                                               # Pod 삭제
kubectl wait --for=condition=Ready pod/stateful-pvc-0 --timeout=180s                             # 다시 뜰 때까지
kubectl get pod stateful-pvc-0                                                                   # 같은 이름으로 돌아왔는가
kubectl get pod stateful-pvc-0 -o jsonpath='{.spec.volumes[0].persistentVolumeClaim.claimName}'  # PVC 는?
kubectl exec stateful-pvc-0 -- ls -A /applog                                                     # 데이터는?
```

```
삭제 전 PVC : volume-stateful-pvc-0
삭제 후 이름 : stateful-pvc-0  Running        ← 같은 이름
삭제 후 PVC : volume-stateful-pvc-0           ← 같은 PVC
파일        : server.log                       ← 데이터 그대로
```

**세 가지가 모두 유지된다.** ReplicaSet이었다면 이름부터 달라졌을 것이다(게시글 503).

> **PVC는 StatefulSet을 지워도 남는다.** 실수로 지웠을 때 데이터를 잃지 않기 위해서다.
> 정말 없앨 생각이면 PVC를 **직접** 지워야 한다.

## 배운 것

- `volumeClaimTemplates`는 **PVC를 찍어내는 틀**이다. Pod마다 하나씩 자동 생성된다.
- PVC 이름은 `<템플릿명>-<StatefulSet명>-<순번>` 이다.
- ReplicaSet은 사람이 만든 **하나의 PVC를 공유**하고, StatefulSet은 **각자 갖는다.**
- Pod을 지워도 **같은 이름 + 같은 PVC + 같은 데이터**로 돌아온다.
- StatefulSet을 지워도 **PVC는 남는다.** 직접 지워야 한다.
