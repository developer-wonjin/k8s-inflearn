# 3) Taint / Toleration — 노드가 Pod을 밀어내기

원문 : https://cafe.naver.com/kubeops/513 (3. Taint / Toleration)

지금까지는 **Pod이 노드를 고르는** 방식이었다.
Taint는 반대다. **노드가 "아무나 오지 마라"고 막는다.**

- **Taint** : 노드에 붙이는 거부 표시
- **Toleration** : Pod이 "나는 그 표시를 견딜 수 있다"고 선언하는 것

## effect 세 가지

| effect | 뜻 |
|---|---|
| `NoSchedule` | 새 Pod을 배치하지 않는다 (이미 있는 건 그대로) |
| `PreferNoSchedule` | 되도록 피하지만 갈 곳이 없으면 배치한다 |
| `NoExecute` | 배치를 막고 **이미 떠 있는 Pod도 쫓아낸다** |

> master 노드에 기본으로 붙는 `node-role.kubernetes.io/control-plane:NoSchedule` 이
> 바로 이것이다. 일반 Pod이 control-plane에 올라가지 않게 막는다.
> **이 클러스터에는 그 taint가 없어서** 지금까지 실습에서 Pod이 master에도 배치됐다.

## 중요 — Toleration은 "허가"일 뿐 "지정"이 아니다

원문이 강조하는 부분이다.

> *"할당 시킬 Node 지정은 Taint/Toleration과 관계 없이 NodeSelector를 사용해야 함"*

Toleration이 있다고 그 노드로 **가는 게 아니다.** 갈 수 있게 될 뿐이다.
특정 노드에 보내려면 `nodeSelector`나 Node Affinity를 함께 써야 한다.

## YAML

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: pod-with-toleration
spec:
  nodeSelector:
    gpu: no1                                   # ① 어디로 갈지는 이쪽이 정한다
  tolerations:
  - effect: NoSchedule                         # ② 그 노드의 거부 표시를 견딘다
    key: hw
    operator: Equal
    value: gpu
  containers:
  - name: container
    image: kubetm/app
  terminationGracePeriodSeconds: 0
```

`operator`는 `Equal`(key와 value가 모두 일치)과 `Exists`(key만 맞으면 됨) 두 가지다.

## 실습 과정

### 1. worker1에 라벨과 Taint를 건다

```bash
clear                                                          # 화면 정리 후 시작
kubectl label nodes k8s-worker1 gpu=no1 --overwrite            # 배치 지정용 라벨
kubectl taint nodes k8s-worker1 hw=gpu:NoSchedule --overwrite  # 거부 표시
kubectl describe node k8s-worker1 | grep -A2 '^Taints'         # 확인
```

```
Taints:             hw=gpu:NoSchedule
```

### 2. toleration 유무로 비교한다

두 Pod 모두 `nodeSelector: {gpu: no1}` 으로 **worker1을 지정**한다.
차이는 `tolerations`가 있느냐뿐이다.

```bash
clear                       # 화면 정리 후 시작
kubectl apply -f - <<'END'  # toleration 없는 Pod 과 있는 Pod
# ... pod-no-toleration, pod-with-toleration YAML ...
END

kubectl get pod -o wide     # 결과 비교
```

```
  pod-no-toleration      Pending    <none>
  pod-with-toleration    Running    k8s-worker1
```

```bash
clear                                                        # 화면 정리 후 시작
kubectl describe pod pod-no-toleration | grep -A4 '^Events'  # 대기 사유
```

```
Warning  FailedScheduling  default-scheduler
  0/3 nodes are available:
    1 node(s) had untolerated taint {hw: gpu},           ← worker1 (taint 때문)
    2 node(s) didn't match Pod's node affinity/selector.  ← master, worker2 (라벨 없음)
```

**탈락 사유가 노드별로 나뉘어 나온다.** 어느 노드가 왜 안 됐는지 정확히 알 수 있다.

### 검증: NoExecute는 이미 떠 있는 Pod도 쫓아내는가

`pod-with-toleration`은 `NoSchedule`만 견딜 수 있게 선언했다.
그 노드에 **다른 taint를 `NoExecute`로** 걸어본다.

```bash
clear                                                          # 화면 정리 후 시작
kubectl get pod -o wide                                        # taint 걸기 전 상태
kubectl taint nodes k8s-worker1 hw2=gpu:NoExecute --overwrite  # NoExecute taint 추가
kubectl get pod -o wide                                        # 20초 뒤 상태
```

```
전:  pod-with-toleration    Running    k8s-worker1
후:  (사라졌다)
```

**멀쩡히 돌던 Pod이 삭제됐다.** `NoExecute`는 배치를 막는 것을 넘어
**그 노드 위에 이미 있는, 견디지 못하는 Pod을 전부 쫓아낸다.**

> 이것은 실제로 쿠버네티스가 스스로 쓰는 기능이다.
> 노드가 `NotReady`가 되면 컨트롤러가 그 노드에
> `node.kubernetes.io/unreachable:NoExecute` taint를 자동으로 건다.
> 그러면 그 위의 Pod들이 쫓겨나 다른 노드에서 다시 뜬다.
>
> 이때 곧바로 쫓아내지 않도록 `tolerationSeconds`를 줄 수 있다.
> 일시적인 네트워크 문제일 수도 있으므로 잠시 기다려보는 것이다.
> ```yaml
> tolerations:
> - key: node.kubernetes.io/unreachable
>   effect: NoExecute
>   tolerationSeconds: 300        # 5분간은 버틴다
> ```

### 정리

```bash
clear                                                                    # 화면 정리 후 시작
kubectl taint nodes k8s-worker1 hw- hw2-                                 # taint 제거 (뒤의 - 가 삭제)
kubectl label nodes k8s-worker1 gpu-                                     # 라벨 제거
kubectl delete pod --all -n default --grace-period=1 --ignore-not-found  # Pod 정리
kubectl describe node k8s-worker1 | grep -A1 '^Taints'                   # Taints: <none> 확인
```

> **taint를 지우지 않고 실습을 끝내면 그 노드에 아무것도 못 뜬다.**
> 다음 실습에서 원인 모를 `Pending`을 만나면 `kubectl describe node` 로 Taints를 먼저 확인한다.

## 배운 것

- Taint는 **노드가 거는 거부 표시**, Toleration은 Pod의 **견딤 선언**이다.
- Toleration은 **허가일 뿐 지정이 아니다.** 어디로 갈지는 `nodeSelector`가 정한다.
- `NoSchedule`은 새 배치만 막고, **`NoExecute`는 이미 있는 Pod도 쫓아낸다.**
- 노드 장애 시 쿠버네티스가 `NoExecute` taint를 자동으로 걸어 Pod을 대피시킨다.
- `tolerationSeconds`로 쫓겨나기까지의 유예를 줄 수 있다.
- 실습 후 taint를 반드시 제거한다. 안 그러면 그 노드가 계속 비어 있게 된다.
