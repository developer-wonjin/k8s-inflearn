# 1) Token 방식으로 Dashboard 로그인하기

원문 : https://cafe.naver.com/kubeops/526 (1. Token 방식으로 Dashboard 로그인하기)

Dashboard는 **자기 권한으로 동작하지 않는다.**
로그인한 사람의 토큰을 그대로 API 서버에 전달할 뿐이다.
그래서 토큰이 가진 권한만큼만 화면에 보인다.

이 문서는 [게시글 522](../522.authentication/README.md)의 ServiceAccount 토큰과
[게시글 525](../525.authorization-rbac/README.md)의 RBAC가 실제로 어떻게 쓰이는지 보여준다.

## 실습 시작 전 정리

```bash
clear                       # 화면 정리 후 시작

# default 네임스페이스의 실습 리소스를 전부 삭제 (시스템 네임스페이스는 건드리지 않는다)
kubectl delete pod,deploy,rs,statefulset,daemonset,job,cronjob \
  --all -n default --grace-period=1 --ignore-not-found

# Service는 kubernetes(클러스터 기본 서비스)만 남기고 삭제
kubectl delete svc -n default \
  --field-selector 'metadata.name!=kubernetes' --ignore-not-found

kubectl get all -n default  # service/kubernetes 만 남으면 정상
```

> **`-n default`를 반드시 붙인다.** `-A`(전 네임스페이스)로 실행하면 `kube-system`,
> `calico-system` 등 클러스터 구동에 필요한 리소스까지 지워져 **클러스터가 망가진다.**
>
> `kubernetes-dashboard` 네임스페이스는 건드리지 않는다.

## 실습 과정

### 1. Dashboard가 어떤 권한을 갖고 있나

```bash
clear                                               # 화면 정리 후 시작
kubectl get sa -n kubernetes-dashboard              # Dashboard 의 ServiceAccount
kubectl get clusterrolebinding | grep -i dashboard  # 어떤 권한이 묶여 있나
```

```
NAME                   SECRETS   AGE
default                0         42d
kubernetes-dashboard   0         42d

kubernetes-dashboard    ClusterRole/kubernetes-dashboard    42d
kubernetes-dashboard2   ClusterRole/cluster-admin           42d
```

ClusterRoleBinding이 **두 개**다. 각각 무엇을 묶고 있는지 본다.

```bash
clear  # 화면 정리 후 시작
kubectl get clusterrolebinding kubernetes-dashboard2 \
  -o jsonpath='roleRef={.roleRef.kind}/{.roleRef.name}  subjects={range .subjects[*]}{.kind}/{.namespace}:{.name}{end}'
```

```
roleRef=ClusterRole/cluster-admin
subjects=ServiceAccount/kubernetes-dashboard:kubernetes-dashboard
```

`kubernetes-dashboard` ServiceAccount에 **`cluster-admin`이 묶여 있다.**

```bash
clear                                       # 화면 정리 후 시작
kubectl describe clusterrole cluster-admin  # 무슨 권한인가
```

```
PolicyRule:
  Resources  Non-Resource URLs  Verbs
  ---------  -----------------  -----
  *.*        []                 [*]
             [*]                [*]
```

**모든 리소스에 모든 동작.** 525에서 직접 만들었던 `cr-02`와 같은 형태의,
쿠버네티스 내장 최고 권한 ClusterRole이다.

### 2. 토큰 생성

522에서 본 대로 **v1.24부터는 토큰이 자동 생성되지 않는다.** 직접 만든다.

```bash
clear  # 화면 정리 후 시작
kubectl create -f - <<'EOF'
apiVersion: v1
kind: Secret
metadata:
  name: kubernetes-dashboard-token
  namespace: kubernetes-dashboard
  annotations:
    kubernetes.io/service-account.name: "kubernetes-dashboard"
type: kubernetes.io/service-account-token
EOF

# 토큰을 꺼낸다 (로그인 화면에 붙여넣을 값)
kubectl -n kubernetes-dashboard get secret kubernetes-dashboard-token \
  -o jsonpath='{.data.token}' | base64 --decode
```

```
secret/kubernetes-dashboard-token created
(978자 길이의 JWT 문자열)
```

### 3. 이 토큰으로 무엇을 할 수 있나

```bash
clear                                                               # 화면 정리 후 시작
SA=system:serviceaccount:kubernetes-dashboard:kubernetes-dashboard  # 확인할 계정
kubectl auth can-i list pods -A --as=$SA                            # 전 네임스페이스 Pod 조회
kubectl auth can-i delete nodes --as=$SA                            # 노드 삭제
kubectl auth can-i create clusterrolebinding --as=$SA               # 권한 부여
```

```
yes
yes
yes
```

**노드를 지우고 권한을 새로 부여하는 것까지 된다.**
이 토큰은 사실상 **클러스터 관리자 자격증명**이다. 취급에 주의해야 한다.

API를 직접 호출해도 통한다.

```bash
clear  # 화면 정리 후 시작
TOK=$(kubectl -n kubernetes-dashboard get secret kubernetes-dashboard-token -o jsonpath='{.data.token}' | base64 -d)
curl -sk -o /dev/null -w 'HTTP %{http_code}\n' https://192.168.56.30:6443/api/v1/nodes -H "Authorization: Bearer $TOK"
```

```
HTTP 200
```

### 4. 접속 경로 두 가지

```bash
clear                                    # 화면 정리 후 시작
kubectl get svc -n kubernetes-dashboard  # Service 확인
```

```
NAME                   TYPE       CLUSTER-IP      PORT(S)         AGE
kubernetes-dashboard   NodePort   10.98.72.224    443:30000/TCP   42d
```

**(A) NodePort로 직접** — 이 클러스터는 30000번이 열려 있다.

```bash
clear                                                                        # 화면 정리 후 시작
curl -sk -o /dev/null -w 'HTTP %{http_code}\n' https://192.168.56.30:30000/  # master 로
curl -sk -o /dev/null -w 'HTTP %{http_code}\n' https://192.168.56.31:30000/  # worker1 로도
```

```
HTTP 200
HTTP 200
```

브라우저에서 `https://192.168.56.30:30000` 으로 접속한 뒤
**로그인 화면에 토큰을 붙여넣으면** 된다 (`Bearer` 없이 토큰만).

**(B) API 서버 proxy 경로** — 원문이 안내하는 방식이다.

```bash
clear  # 화면 정리 후 시작
TOK=$(kubectl -n kubernetes-dashboard get secret kubernetes-dashboard-token -o jsonpath='{.data.token}' | base64 -d)
URL='https://192.168.56.30:6443/api/v1/namespaces/kubernetes-dashboard/services/https:kubernetes-dashboard:/proxy/'

curl -sk -o /dev/null -w '토큰 있이 HTTP %{http_code}\n' "$URL" -H "Authorization: Bearer $TOK"
curl -sk -o /dev/null -w '토큰 없이 HTTP %{http_code}\n' "$URL"
```

```
토큰 있이 HTTP 200
토큰 없이 HTTP 403
```

이 경로는 **API 서버를 통과**하므로 요청 자체에 인증이 필요하다.
브라우저는 헤더를 직접 넣을 수 없어서, 원문이 ModHeader 확장 프로그램을 안내하는 것이다.

## 브라우저 쪽 작업 (이 문서에서는 미실습)

원문의 1-4 ~ 1-7은 **PC의 브라우저에서** 하는 작업이라 서버에서 재현할 수 없다.

| 단계 | 내용 |
|---|---|
| 1-4 | master의 인증서를 `.cer`로 변환해 PC에 설치 |
| 1-5 | Chrome 확장 **ModHeader** 설치 |
| 1-6 | 헤더에 `Authorization: Bearer <토큰>` 입력 |
| 1-7 | Dashboard 로그인 화면에 토큰만(Bearer 없이) 입력 |

**(A) NodePort 방식을 쓰면 1-4~1-6을 건너뛸 수 있다.**
API 서버를 안 거치므로 헤더 조작이 필요 없고, 로그인 화면에 토큰만 넣으면 된다.

인증서 변환이 필요한 경우의 명령은 이렇다.

```bash
clear                                                           # 화면 정리 후 시작
grep 'client-certificate-data' ~/.kube/config | head -n 1 | awk '{print $2}' | base64 -d > client.crt
grep 'client-key-data' ~/.kube/config | head -n 1 | awk '{print $2}' | base64 -d > client.key
openssl pkcs12 -export -clcerts -inkey client.key -in client.crt -out client.p12 -name "k8s-master-30"
openssl pkcs12 -in client.p12 -clcerts -nokeys -out client.cer  # PC 에 설치할 인증서
```

> 비밀번호를 묻는 곳에서는 **그냥 엔터**를 친다.
> 만들어진 `client.key`·`client.p12`는 **관리자 권한 그 자체**라 실습 후 반드시 지운다.

### 정리

```bash
clear                                                                                        # 화면 정리 후 시작
kubectl delete secret kubernetes-dashboard-token -n kubernetes-dashboard --ignore-not-found  # 토큰 삭제
rm -f client.crt client.key client.p12 client.cer                                            # 인증서 파일 삭제
```

> **`kubernetes-dashboard` ServiceAccount 와 ClusterRoleBinding 은 지우지 않는다.**
> 클러스터 설치 때부터 있던 것이라 지우면 Dashboard 가 동작하지 않는다.
> 이 실습에서 만든 것은 **Secret 하나뿐**이다.

## 배운 것

- Dashboard는 **자기 권한으로 동작하지 않는다.** 로그인한 토큰을 그대로 전달한다.
- 이 클러스터의 Dashboard SA에는 **`cluster-admin`이 묶여 있다.** 토큰이 곧 관리자 권한이다.
- 토큰 Secret은 v1.24부터 **직접 만들어야** 한다 (522와 동일).
- 접속은 두 가지 — **NodePort**(간단, 헤더 불필요)와 **API 서버 proxy**(헤더 필요).
- 로그인 화면에는 `Bearer` 없이 **토큰 문자열만** 넣는다.
